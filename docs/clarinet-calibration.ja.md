# クラリネットモデルとコピー合成評価

[English](clarinet-calibration.md)

フィジカルクラリネットは、サンプルを使わない16ボイスの楽器です。逆転したボア反射を備えた分数半周期遅延が、閉管・開管の管共鳴を提供します。境界付き非線形圧力流近似が、リード信号と呼吸ノイズで励起します。遅いランニング平均が励起の直流成分を除去します。これは、特定のマウスピース、指使い、演奏者、またはベル放射パターンを再構築するのではなく、現象学的リード/ボアモデルです。

息の圧力、リードの硬さ、息のノイズは発音中のボイスに影響します。アタックとリリースは共有のADSRを制御します。CC7は音量を制御し、CC11は息の駆動と出力エクスプレッションを20 msにわたって滑らかにします。ピッチベンドは音が出るボアを再調整します。ディレイ用ストレージは`prepare`に割り当てられ、コールバック処理と制御変更では何も割り当てません。リセットは同じシードされた励起を再現します。

<a id="reference-and-preparation"></a>
## 参照と準備

[イオワ大学BbクラリネットMISページ](https://theremin.music.uiowa.edu/MISBbclarinet.html)では、1998年8月3日にWendell Johnson無響室でNeumann KM 84を使用し、16ビット、44.1 kHzモノラルで録音された、Glenn BowenによるBuffet R13 Bbクラリネットが特定されています。[MISコレクション利用規約](https://theremin.music.uiowa.edu/MIS.html)により、これらの録音は制限なく任意のプロジェクトでダウンロードおよび使用することが可能です。オンライン準備実行では、両ページが元のキャプチャファイルの横にキャッシュされます。

固定したコホートは、`pp`、`mf`、`ff`で`D3B3`、`C4B4`、`C5B5`の録音を使用します：34音高、MIDI 50–83、102のノートインスタンス。ファイル名はコンサート音高を識別します：D3、C4、C5の基音はそれぞれ約147、262、523 Hzです。これらのラベルを楽器のBb指定に合わせて移調しないでください。偶数音高のすべてのダイナミクスはトレーニング（51ノート）に属し、奇数音高は検証（51ノート）に属します。これは、独立した楽器やプレイヤーではなく、同じ楽器、プレイヤー、録音設定内の音高を保持します。

時間領域は、キャプチャピークの2%で5 ms RMSエンベロープを使用して検出され、短いギャップは統合されます。各ノートは5 msのプレロールで始まり、検出された領域の250 ms後に終了し、その後3秒にクロップまたはゼロ埋めされ、24 kHzにポリフェーズ再サンプリングされます。検出された領域の長さは概ね保持時間を供給し、レンダラーでは2.98秒に制限されます。そのため、一部のノートは保持されたウィンドウ全体にわたって持続します；T90はそのウィンドウでのエネルギータイミングを測定し、完全な物理的なリリースを測定するわけではありません。ベロシティマップは`pp/mf/ff`から0.35/0.65/0.95に設定されています；これらは開発上の選択であり、測定されたMIDIベロシティではありません。測定された録音デチューニングはレンダラーに渡されます。ソースと準備済みデータのハッシュ、時刻、ピッチは`tools/eval/references/clarinet-notes.json`に保持されます。マニフェストのチェックサムはCRLFをLFに正規化し、Gitのプラットフォームの行末が保持された校正を無効にしないようにします。

<a id="calibration-and-results"></a>
## 校正と結果

実際の24 kHz Rust PCMを使用して、トレーニングノートに4つのコントロールが設定されました：圧力、リード硬さ、ノイズ、アタック。シード付き差分進化は4回のイテレーション、集団倍率は4、ポリッシングはなし（80回の評価）を使用します。目的は位相重み付きログメルL1プラス`0.006 × envelope dB error + 0.15 × T90 error in seconds`です。検索境界、トレーニングID、初期コントロール、フル精度の結果は`clarinet-training-fit.json`に保持され、丸められたコントロールは工場出荷時のデフォルトになります。この短い境界付き検索はグローバル最適ではありません。ベースラインは、以前にリリースされた楽器ではなく、校正前の新しいクラリネットです。

最終評価では、ネイティブ48 kHzでの実際の丸められた工場出荷時のデフォルト値を使用し、24 kHzにポリフェーズリサンプリングします。両方の信号は、メトリクスで使う因果的な30 Hzハイパスフィルターと、0.1への全ノートRMS正規化を受けます。タイムウォーピングやフレームごとのゲイン調整は行いません。ログメル構成は[physical pack evaluator](physical-pack.ja.md)と同じです：512/2048 Hannウィンドウ、240サンプルホップ、30 Hzから10 kHzまでの64バンド、アタック/ボディ/テールウェイト付け0.3/0.3/0.4。エラーが低いほど良いです。

| ホールドアウト測定、51音 | 初期制御 | 校正済み工場出荷値 | 変化 |
| --- | ---: | ---: | ---: |
| 位相重み付きログ-メルL1 | 0.079209 | 0.057546 | 27.35%低い |
| アタックログメルL1 | 0.086815 | 0.020081 | 76.87%低い |
| ボディログメルL1 | 0.092661 | 0.087211 | 5.88%低い |
| テールログメルL1 | 0.063416 | 0.063396 | 0.03%低い |
| エンベロープL1 | 4.4996 dB | 4.3681 dB | 2.92%低い |
| T90絶対誤差 | 0.28772秒 | 0.29116秒 | 1.19%高 |

トレーニング中のmelは0.079556から0.058190に低下します。2,000回の再標本化を用いた対応ありブートストラップは、各ピッチのすべてのダイナミクスを保持します。ホールドアウトmel差分の記述的95%間隔は[−0.022670, −0.020565]です。改善の大部分はアタックにあり、テール改善は結論付けられず、エネルギータイミングはわずかに悪化します。これらはモデル開発後のコピー忠実度指標であり、知覚的品質スコアではありません。24 kHzのリプレイにより、ホールドアウトmelは0.077159から0.055598に改善します。ネイティブレートのレポート、ハッシュ、各ノートエラーは、`tools/eval/references/clarinet-validation*.json`のコホートとともにコミットされます。

独立した定常状態FFTプローブは、MIDI 48〜93を3つのベロシティと両方のレートでカバーします。参照範囲50〜83では、最大絶対チューニングエラーは24 kHzで8.89セント、48 kHzで4.93セントです。その範囲外では、24 kHzプローブは19.38セントに達します。数値を検証するRustテストは、奇数次高調波、直流、極端なコントロール/レート、リリース後のボイス解放、決定論的リセット、CC7/CC11、ブロックサイズを横断したイベント処理もカバーします。セッションテストは、サウンドフォントなしでネイティブ楽器を保存、開く、レンダリングします。

48 kHzステレオ、256フレームの16声クラリネットのコールバックは、開発機上で512ブロックあたり平均0.016 ms、p99 0.017 msを記録しています。タイミング、FFT行、プリセット回帰ハッシュ、レベルを揃えた試聴記録は`tools/eval/references/physical-next-regressions.json`にあります。ネイティブデモエクスポートはフルスケールでサンプルがありません；リスニングバージョンはフレーズ全体のRMS 0.1を使用します。

<a id="reproducing-and-auditioning"></a>
## 再現と試聴

```sh
cargo build --release -p auris-synth --example physical_fit_render
uv run tools/eval/fetch_clarinet_reference.py target/physical-next/clarinet-reference --lock tools/eval/references/clarinet-notes.json
uv run tools/eval/clarinet_copy.py target/physical-next/clarinet-reference <new-worker> target/physical-next/clarinet-validation.json --baseline <initial-clarinet-worker> --rate 48000 --calibration tools/eval/references/clarinet-training-fit.json
cargo run -p auris-session --example clarinet_demo -- target/physical-next/clarinet-demo
cargo run --release -p auris-synth --example physical_bench -- --clarinet
```

Windowsでは`.exe`のサフィックスを使用してください。アーカイブされた初期ワーカーはレポート内のSHA-256で識別され、校正された制御の採用以前のものでした。`--baseline`がない場合、評価者は`--params`または`--fit-bounds`経由で通過した候補と現在の工場を比較できます。`--offline`はネットワークリクエストなしでキャッシュされたキャプチャを作成し、凍結されたハッシュも検証します。デモは編集可能なプロジェクトとネイティブのWAVファイルを新しい出力ディレクトリに保存します。
