# オーディオ素材操作の実装と動作検証

AIエージェントから、音声素材の検索、取り込み、切り出し・逆再生、配置、EQ・フェードまで操作できるようにしました。既存のクリップ編集・ミキサー機能と新しい `audio_assets` を組み合わせています。使い方は [agent-audio-assets.md](agent-audio-assets.md) にまとめています。

## 実装

- ローカル検索はファイル名と相対パスを対象とし、Music／Downloadsまたは指定ディレクトリを検索します。
- ネット検索はWikimedia Commonsを使い、APIキーなしで音声ファイルと出典・作者・ライセンス情報を取得します。直接URLの取り込みにも対応しています。
- 切り出し・逆再生は新しいWAVを作成します。元ファイルと同じ素材を使う別クリップを保持し、Undo／Redo、保存・再読み込みに対応します。加工は1回あたり600秒以内です。
- EQは既存の `mixer_graph` 経由でオーディオトラックに挿入します。フェード・ゲイン・移動・複製は `edit_clip` を使います。
- ネット処理とファイル処理はUI外のワーカーで行い、編集が競合した場合やキャンセル時には未反映の結果を破棄します。パネルのネット操作には既存の権限処理を通します。
- 出典、ファイルのSHA-256、加工履歴を音源メタデータとして保存します。ライセンス表記は取得・入力された情報であり、独立した権利検証ではありません。

## 自動テスト

`cargo test --workspace` は4,536件成功、失敗0件、明示実行用など35件はignoreでした。`cargo clippy --workspace --all-targets`、`cargo fmt --all -- --check` も成功しました。

追加のセッションテスト10件と保存済みツール経路のテストで、ステレオのサンプル単位の反転、元ファイル・共有クリップの保持、Undo／Redo、保存して開き直す処理、44.1 kHzの保持、古いリビジョン・別セッション・キャンセルの拒否、ローカル検索のページング、HTTPリダイレクト、壊れた音声・過大ダウンロードの拒否と一時ファイル削除、出典保存、権限を検証しました。

EQの試験は100 Hzと4 kHzを含む信号をエージェント経由で取り込み、1 kHzのハイパスを挿入してレンダーします。100 Hzの振幅が元の3%未満、4 kHzが元の90%以上で、元ファイルは変化しないことを確認しました。

実装中に、Windowsで開いた一時ファイルをWAVライターが置き換えられない問題と、48 kHz以外の加工WAVに正しいヘッダー値が必要な点を修正しました。既存のモック通信テスト2件は、増えたツールカタログと画像／出力予約が32Kを超えるため、テスト内の予算を64Kに変更しました。製品の既定値は変更しておらず、Ollamaの実モデルは使っていません。

## Codexによるパネル操作

Codex CLIの `gpt-6.1-sol` を使用し、実際のAgent Panelホストを通るGPUIテストで1回検証しました。空の検証用プロジェクト、標準プロンプト、64Kコンテキスト、独立したbypass権限設定で実行しています。所要時間は約160秒でした。

Codexは次の操作を完了しました。

1. Commonsでドアのきしみ音を検索し、出典・作者・ライセンスを保存して取り込み。
2. 元音声の0〜1.8秒を切り出して逆再生し、曲頭に配置。
3. トラックEQの180 Hzハイパスと20 ms／50 msのフェードを適用。
4. 指定されたローカルフォルダーを名前検索し、元のOGGを別トラックの2小節目に配置。ネット素材とSHA-256が一致することを確認。
5. ソース、加工履歴、EQパラメーター、各トラックとミックスの音声を読み返し、8秒のWAVを書き出し。

初回の書き出しは、音声配置の終端が約7.094秒であるのに8秒を指定したため拒否されました。Codexはツール説明を読み直し、既存の楽器トラックにノート0個の空クリップを追加して8秒の終端を確保し、再試行しました。この失敗1件と修正は履歴に残しています。

最終WAVは48 kHz・ステレオ・24 bit・384,000フレーム。測定値は約−23.81 LUFS、−5.31 dBTPで、フルスケールのサンプルは0です。`verify_render` はPASSでした。終端RMSの返値はnullなので、有限の数値としては報告していません。
