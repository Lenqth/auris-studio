# 標準プロンプトの改訂とフロンティアモデルでの作曲検証

この文書は、今回の依頼に対する実験報告です。音楽的な好みの評価と、作曲・書き出しの成立を分けて記録します。

## 変更内容

標準プロンプトの冒頭に、主題の反復と変化、フレーズの行き先、和声とベースの動き、セクションの対比、伴奏の役割、歌詞の展開と韻律、曲全体の完成と終止を置きました。メロディー・歌詞・グルーヴ・和声のどこから書くか、伴奏を直接書くか生成レシピを使うかは、依頼に合わせてモデルが選びます。

操作上の約束は別のテキストにまとめています。ID、音符の単位、更新リビジョン、既存素材の保護、歌声テイクの鮮度、実ファイルの測定、聴取と測定の区別は維持しています。局所修正は問題ごとに原則2回までとし、部分的な推敲より曲全体を完成させることを優先します。

- 作曲指針: `crates/auris-agent/src/prompts/composition.md`
- 操作契約: `crates/auris-agent/src/prompts/live-tools.md`
- 組み立て: `crates/auris-agent/src/lib.rs` の `default_system_prompt`

CodexとClaude Codeは同じ標準指針を受け取ります。設定画面で保存したカスタムプロンプトは置き換えません。標準に戻して適用した場合、または保存値が空の場合に、新しい標準を使います。

## 実験条件

変更前のコミットは `bb06eae55064ccaf9eeb7b549afd900cdf57c3a3` です。Codex CLI 0.163.0の `gpt-6.1-sol` と、Claude Code 2.1.309の `opus` を使いました。Claudeの具体的な解決先モデルIDは取得していないため、指定したエイリアスとして記録します。Ollamaによる実推論と外部の音声批評は使っていません。

課題は `tools/eval/references/frontier-composition-v1.json` に固定しています。

| 課題 | 構成 | 指定 |
| --- | --- | --- |
| 器楽曲 | Aメロ8・つなぎ4・サビ8・終わり4小節 | 120 BPM、4/4、ハ長調、24小節＝48秒。主旋律・鍵盤・ベース・控えめなドラム |
| 歌もの | イントロ2・一番8・サビ8・間奏2・二番8・ラストサビ8・アウトロ4小節 | 100 BPM、4/4、ハ長調、40小節。100 BPM固定なら96秒。日本語の歌とピアノ |

各モデル・課題・条件につき1回の開発試験です。実際のAgent Panelのホスト、権限処理、ライブ編集、音声レンダーを通すGPUIテストを使用しました。各試行は空の別プロジェクトで、構成作成と読み返し・納品の2ターンです。1ターンの上限は900秒。標準のツール群を使い、実験用の候補比較ツールや編曲ハーネスは無効にしています。

初稿は共有コンテキストのモック回帰テスト2件で上限超過になりました。作曲指針を保って操作説明の重複を整理し、最終版を再試験しました。初稿の4試行も `after-codex` / `after-claude` として保持しています。正式な比較は `before-*` と `final-*` の8試行です。生成の乱数は揃えられないため、独立生成の比較であり、1回の結果から改善率や安定性の向上は推定しません。

実行ファイル・DLL・課題・ソース差分・成果物のハッシュ、全ツール履歴、各ターンの譜面を `target/frontier-prompt-2026-10-24/` に保存しています。最終版のソース差分には、外出ししたプロンプト本文も含まれています。

## 歌声合成の扱い

GPUIテストはユーザー設定を隔離するため、`list_voices` は空でした。パネル内での歌声合成完了を示す試験ではありません。元のWAVはガイド音声または伴奏であり、VOICEVOX歌唱とは区別します。

変更前と最終版の完成譜面を複製し、同じVOICEVOX 0.26.0の「ずんだもん / ノーマル」、seed 0で別途合成しました。音符・歌詞・和声・構成・オートメーションを変更していないことを検査します。未合成として歌トラックをミュートした試行は、試聴用の複製だけでミュートを解除し、その差分を記録します。

合成した歌声はガイド音声と音量が異なります。例えば変更前のClaude曲は、元のミックス設定で合成後に最大約+2.49 dBTPとなりました。比較用WAVは同じレンダー経路で再計測し、必要なときだけ全体に一定ゲインを適用して−1 dBTP以下に収めます。元のクリッピングした書き出しも保持し、修正前の問題を消しません。これは納品用の処理であり、エージェントによるミックス改善とは数えません。

比較ページ用のコピーでは、さらに各ペアの積分ラウドネスを揃えます。音量差が好みに与える影響を小さくするための処理で、元の音源・譜面・測定値はそのまま残します。

## 結果

全8試行で、2ターンのモデル実行とWAV/MIDIファイルの生成は完了しました。これは、依頼の全条件や歌声合成を満たしたという意味ではありません。元のパネルWAVにフルスケール到達サンプルはありませんでした。

| モデル | 課題 | 元のWAV秒数: 変更前 → 最終版 | 引数・ツール失敗回数: 変更前 → 最終版 |
| --- | --- | ---: | ---: |
| Codex | 器楽曲 | 48.000 → 48.000 | 4 → 0 |
| Codex | 歌もの | 96.000 → 96.000 | 2 → 0 |
| Claude | 器楽曲 | 48.000 → 48.000 | 0 → 1 |
| Claude | 歌もの | 96.000 → 96.736 | 0 → 0 |

Claudeの最終歌ものは39小節で92 BPM、40小節で82 BPMに減速しています。40小節の範囲は正しいものの、100 BPM固定という厳密な条件には一致しません。残響の追加やレンダーの長さの不具合ではありません。元のテンポを改変せず比較に残しました。モデルの裁量を増やしたときに、指定条件との境界を確認する必要がある例です。

失敗回数はこの試行で観察した値であり、成功率の推定ではありません。処理時間の短縮も確認できていません。例えばCodex器楽曲のテスト内経過時間は約546→706秒、Claude歌ものは約330→640秒でした。並行実行やビルドの負荷もあるため、速度ベンチマークには使えません。

譜面から確認できた選択の変化は、次のとおりです。

- Codex器楽曲では、変更前の伴奏14クリップが生成レシピ付きだったのに対し、最終版では鍵盤・ベース・ドラムも直接音符を記述しました。伴奏を自分で書く選択肢が実際に使われました。これ自体を品質の優劣とは数えません。
- Claude器楽曲では、変更前は終端まで保持した音をマスターゲインのフェードで収めていました。最終版は主要パートの最後の音を47秒で離し、48秒まで減衰の時間を置き、マスターのフェードはありません。実WAVの終端RMSは約−60.7 dBでした。終止を譜面と音の減衰で設計する例になっています。
- 最終版の歌ものは両モデルとも二番で場面を進めました。Codexは交差点を渡り、感謝を送る描写、Claudeは言えなかった言葉を翌日伝える描写です。サビの中心語と旋律を繰り返しています。変更前にも二番とラストサビは存在したため、この点を新規の改善とは主張しません。

別途合成した4曲はすべて `inspect_singer` のテイク状態が `current` でした。以下は後半の歌唱の検査です。

| 条件 | 二番の音符 | ラストサビの音符 | 後半の歌詞未割り当て | 各音符区間のRMSが−60 dBFS未満 |
| --- | ---: | ---: | ---: | ---: |
| Codex・変更前 | 45 | 40 | 0 | 0 |
| Codex・最終版 | 44 | 50 | 0 | 0 |
| Claude・変更前 | 37 | 35 | 0 | 0 |
| Claude・最終版 | 45 | 42 | 0 | 0 |

最終版の歌声入りミックスは、Codexが96.000秒・約−1.10 dBTP、Claudeが96.736秒・約−4.61 dBTP。いずれもフルスケール到達は0です。両曲とも歌唱テイクが最後の歌唱音まで続いていることを確認しました。音符区間のRMSは無音を見つける検査であり、正しい発音や各音の聞き取りを証明するものではありません。

MIDIも独立に読み直しました。現行のエクスポーターはinstrument/drumトラックを対象とし、今回の歌もののMIDIにはsingerトラックの歌譜が含まれていません。例えばClaude最終版の463音はピアノ右手354音＋左手109音で、「歌167音を含む」というモデルの最終説明とは一致しません。歌譜の元データは保存したプロジェクト／JSONです。また、MIDI末尾は最後のイベントまでなので、WAVに含まれる終端の無音時間と一致しない場合があります。ファイルがあることやモデルの説明だけを納品検証にしない理由です。

## 成果物と再確認

機械可読の集計は `tools/eval/references/frontier-prompt-evaluation-2026-10-24.json` にあります。全12試行を含み、初稿や条件差を除外していません。個々の完全な履歴・元の音源・実行ファイルはローカルの `target/frontier-prompt-2026-10-24/` にあります。

- `listening/listening.html`: 音量を揃え、条件名を伏せた4ペアの試聴ページ。対応表は別の `private-key.json`。好みの採点は未実施。
- `final-codex/instrumental_arc-01/result.wav` / `final-claude/instrumental_arc-01/result.wav`: 最終版の器楽曲。
- `synthesis/final-codex/audition.wav` / `synthesis/final-claude/audition.wav`: 最終版の歌声入りミックス。
- 同じ合成フォルダーの `Song.auris` と `Audio/`: 歌唱テイクを含むプロジェクト。`audit.json`、`take-inspection.json`、`audition-preparation.json`、`audition-render.json` が合成と試聴用処理の記録。

実モデル試験を再実行するには、`cargo test -p auris-gpui --bins --no-run --message-format=json` で得たテスト実行ファイルを `tools/eval/composition_quality.py run` に渡します。今回のmanifest、`--backend codex --model gpt-6.1-sol` または `--backend claude --model opus`、`--repetitions 1 --timeout 900 --no-candidate-tools` を使い、出力先は毎回新しいフォルダーにします。生成結果が同じになることは保証されません。

コード検証は `cargo test -p auris-agent`（119件）、`cargo test -p auris-gpui --bins`（1,154件）、`cargo clippy --workspace --all-targets`、`cargo fmt --all --check`。評価ランナーのpytest 9件とRuffも通しています。Ollamaという名前のモック回帰テストはありますが、実際のローカル言語モデルには接続していません。

## 検証の限界

音符や歌詞の存在、テイクの鮮度、区間ごとの非無音、ピーク・終端の測定は、自然な発音、歌詞の聞き取りやすさ、主題の魅力、伴奏の心地よさを証明しません。今回、モデル自身に音声を直接聴かせる評価も、人間によるブラインド採点も行っていません。比較ページの好みの評価は未判定です。

この試験で確認するのは、改訂した標準プロンプトで実曲を完成・書き出せるか、後半を含む譜面を実際に歌声合成できるか、どのような作曲上の選択が観察できるかです。「変更後の曲のほうが優れている」という結論には、聴取評価と追加の独立試行が必要です。
