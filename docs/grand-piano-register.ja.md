# 鍵盤全体のグランドピアノ

[English](grand-piano-register.md)

2026-10-26 の改訂では、Physical Piano の弦、ハンマー、響板を作り直し、C1 から C8 までの Steinway の録音に合わせて整音しました。[以前の較正](grand-piano-calibration.ja.md)は旧構造のまま C3〜G4 だけを対象にしていました。鍵盤全体で測ると、旧構造にはどの設定でも取り除けない欠陥が4つありました。

* **一段だけの減衰。** グランドピアノの音はまず速く減衰し、その後長く鳴り続けます。C4 mf の録音では、基音が最初の1秒で約 40 dB/s、その後は約 2 dB/s で減衰します。旧モデルは C3 以上でほぼ一定の 9 dB/s で減衰したため、中音域の音は最初は減衰が遅すぎ、後半は速すぎました（8 秒で -74 dB。録音はノイズフロアの -35 dB）。
* **損失に音域の違いがない。** どの基音も公称 T60 が同じだったため、低音は早く消え、C8 は約6秒鳴り続けました。
* **両端でスペクトルの釣り合いが誤っている。** C1/C2 では部分音 3〜7 が、ほとんど放射されない基音より 20〜30 dB 大きいのに、旧モデルでは基音より小さくなっていました。高音の第2部分音は 20〜25 dB 強すぎました。ハンマーの接触時間を弦の周期の一部に制限していたためです。
* **ノックがない。** 高音を打つと、響板から短く広帯域のノックが鳴ります。C8 では弦の音と同じくらいの大きさです。旧モデルにはありませんでした。

## モデル

**弦と駒。** ユニゾンの各弦の各部分音は、減衰しながら回転するフェーザーです。駒は、弦が共有する運動の一部だけを吸収します。結合と直交する運動は弦自身の損失だけで減衰します。一緒に打たれたユニゾンはまず速く響板へ流れ込み、わずかな調律のずれと不均一なハンマーが残した運動がアフターサウンドとして鳴り続けます。これは結合したピアノ弦についての Weinreich の説明です。65 Hz 未満の単弦には弱く結合した第2の偏波があり、同じ2段階の減衰になります。置き換えた凸混合は逆に「差分」の運動を減衰させており、物理とは反対でした。この射影は吸収割合が 0〜1 のとき受動的で、エネルギーが増えないことをテストで確かめています。

**損失。** 基音のアフターサウンドの減衰はフィットした曲線に従い、低音から中音では 1.3〜1.8 dB/s、C7 で 14 dB/s、C8 で 43 dB/s です。上の部分音には周波数の2乗に比例する内部摩擦が加わります。Resonance Decay と Damping はこの曲線を拡大縮小し、工場値ではそのまま再現します。ユニゾンの調律のずれは Hz で上限を設けたので、最高音域が 4 Hz でうなることはなくなりました。単弦と2本弦では最大96部分音、3本弦では64部分音を計算します。

**ハンマー。** フェルトが弦に触れている時間は、mf で C1 の 4.3 ms から C4 の 1.9 ms、C8 の 0.4 ms まで短くなります。高音では周期より長く触れるため、ほぼ純音に近くなります。接触パルスは時間軸を歪めた正弦のべき乗で、音色ごとに表にします。フェルトの硬い芯による短いガンマパルスはベロシティとともに大きくなり、強打の高い部分音を保ちます。ベロシティは、ハンマーが何を励振するかを変えますが、それだけで音量は変えません。打鍵を同じハンマーの mf と比べ、響板の放射で重み付けした8帯域で駆動を調整するため、音量は楽器のベロシティ則を保ちます。

**放射。** 出力は駒にかかる力、つまり各モードの駒での傾きです。197 Hz の2次ハイパスが、最初のモードより低い周波数を響板があまり放射しないことを表し、その後にフィットした12帯域の色付けが続きます。音域ごとのゲイン曲線が、調律師の整音と同じように弦の音量をそろえます。

**ノック。** 打鍵ごとに響板も直接励振されます。音で決まるシードの帯域制限ノイズで、ハンマーとともに立ち上がり、100 dB/s で減衰し、40 Hz のハイパスと 1.3 kHz のローパスを通ります。弦に合わせてフィットした放射フィルターの後で混ぜ、ダンパーでは止まりません。レンダーは決定論的で、ブロックサイズに依存しません。

**ダンパーとペダル。** ピアノの Release はダンパーです。共通エンベロープと同じく 80 dB 減衰させるまでの時間で、低音ほど長くなる曲線を掛けます。F6 より上の鍵にはダンパーがなく、離鍵後も鳴り続けます。サステインペダルはすべてのダンパーを上げ、離鍵後にすでに下り始めたダンパーも上げます。ダンパー曲線には参照録音がなく、フィットしていません。

## 参照

University of Iowa の [Steinway model B 録音](https://theremin.music.uiowa.edu/MISpiano.html)（演奏 Evan Mazunik）から、C1〜C8 のすべての C の mf と、C2、C4、C6、C7 の pp/ff を使います。pp の C6 と C7 は録音のノイズフロアから数 dB しか離れていないため使わず、固定した16ファイルのうち14ファイルをフィットに使います。URL、サイズ、ハッシュは [piano-register-captures.json](../tools/eval/references/piano-register-captures.json) にあります。最後のメル段階には、グランドピアノ較正の訓練用6音（C3、G3、E4 の mf/ff）も加えます。そのうち9音（C3、E3、G3、E4、G4 の pp と、E3、G4 の mf/ff）はどのフィットにも使わず、下のホールドアウト検証に使います。

## 測定とフィット

測定は 24 kHz でアタックを揃えた音に対して 25 ms ごとに行い、各ファイル自身のノイズフロアを考慮します。

| 測定 | 比べるもの |
| --- | --- |
| decay | 最大12個の部分音それぞれの、100 ms 時点の自分に対する音量。レンダーには録音のフロアを加える |
| envelope | 100 ms に対する広帯域の音量。同じフロアを通す |
| spectrum | 50〜400 ms の部分音の音量。合計に対する比 |
| level | 50〜500 ms の音量。開始時に固定したオフセットを通して同じ強さの C4 と比べる |
| knock | 20/60/120 ms での 0.6 f0 未満の帯域パワー。同じオフセットを通した絶対値で、フロアより上だけ |

範囲を制限した座標探索で、音域のアンカーはそのアンカーの音だけ、共通の係数はすべての音で、段階ごとにフィットします。decay 段階（decay と envelope）、spectrum 段階（spectrum と level）、knock 段階（knock と level）です。滑らかさの罰則で、音域曲線と響板ゲインがジグザグになるのを防ぎます。その後、C4 の3つの強さで差分進化を行い、座標探索が見逃したパルス形状と硬い芯の増え方を見つけ、そこから各段階をやり直しました。level のゲイン曲線は録音の1秒音量プロファイルから決め、手で滑らかにしました。C4 より下のノックは部分音に隠れるので C4 の値を使います。

続いて、プロジェクトの時間メル距離が、部分音の測定では見逃していた欠陥を明らかにしました。響板が 320〜500 Hz を持ち上げていましたが、C3〜C4 では基音が第2部分音より大きくなければなりません。最後の段階では、この距離で、ハンマー、打弦位置、響板、ハイパス、Excitation Position をフィットし直します。対象はこの14音とグランドピアノ較正の訓練用6音で、level を歯止めにします。この段階で響板のピークは 210〜320 Hz へ下がり、放射のハイパスは 93 Hz から 197 Hz になりました。[piano-register-fit.json](../tools/eval/references/piano-register-fit.json) に手順と音色の値を記録しています。

## 結果

工場設定で、変更前と変更後の固定したワーカーが実際に出力した Rust の PCM です。すべての音は [piano-register-evaluation.json](../tools/eval/references/piano-register-evaluation.json) にあります。フィットに使った14音の平均絶対距離は次のとおりです。

| 測定 | 変更前 | 変更後 |
| --- | ---: | ---: |
| decay | 17.75 dB | 4.70 dB |
| envelope | 4.39 dB | 1.40 dB |
| spectrum | 8.86 dB | 4.30 dB |
| level | 7.11 dB | 1.76 dB |
| knock | 35.61 dB | 3.44 dB |

これらは訓練データです。独立した検証は、グランドピアノ較正の音でのメル距離です。48 kHz での結果（[レポート](../tools/eval/references/piano-register-grand-validation.json)）:

| 音 | 1 s | 3 s | 6 s |
| --- | ---: | ---: | ---: |
| 較正の訓練用（6） | 0.1588 → 0.1533 | 0.2052 → 0.1947 | 0.2437 → 0.2260 |
| 較正の検証用（12） | 0.1611 → 0.1520 | 0.2032 → 0.1855 | 0.2410 → 0.2174 |
| どのフィットにも使っていない（9） | 0.1742 → 0.1639 (-5.9%) | 0.2190 → 0.1995 (-8.9%) | 0.2595 → 0.2332 (-10.1%) |

どの窓でも、ホールドアウトした9音のうち7音が改善しました。改善が最も大きいのは pp で、3秒で 5〜30% です。E3 の mf/ff はそれぞれ 17% と 12% 悪化し、較正の訓練用では G3 mf が 24% 悪化しました。24 kHz でのホールドアウトの改善は 5.1%、7.8%、8.8% です。

出力倍率は、3つの強さの C3〜G4 の音の3秒 RMS の中央値を保ちます。0.1867 が 0.0776 になり、Level は -12 dB のままです。工場の Excitation Position は、メル段階の結果から 0.2444 になります。ベロシティ則も保ちます。0.65 に対して、0.35 と 0.95 は変更前はどの音高でも -7.0 dB と +4.5 dB でした。変更後は C2 で -8.4/+6.1、C4 で -7.2/+5.0、C7 で -6.7/+5.1 です。録音は C4 で pp から ff まで約 25 dB ありますが、それには合わせず、既存の曲の強弱を保ちます。

48 kHz、256 フレームのブロックで24ボイスを保持したとき、コールバックの負荷はほぼ変わりません。バックグラウンド負荷がある状態で対にした2回の測定では 2.18 対 2.07 ms と 1.88 対 1.90 ms、負荷のないマシンでの以前のビルドでは 1.25 対 1.0 ms でした。24音を1つのブロックで打つと、そのブロックが約 0.4 ms 増えます。これは開発マシンでの測定であり、レイテンシの保証ではありません。

## 試聴と限界

`target/piano-register/audition/` に、鍵盤を上がっていく音、ベロシティの段階、ペダルを使ったフレーズ、スタッカートとダンパーがあります。どれも同じイベントで旧→新の順に鳴らし、RMS をそろえています。また、録音の mf の音と新しいピアノを交互に並べたファイルもあります。これらは開発用の出力で、リリースには含めません。

この整音を制約しているのは、1台のピアノ、1つのマイク位置、3つの強さの表記だけです。ダンパー、リリース、ペダルには参照がなく、高音部分音の下に隠れた 1.3 kHz 以上のノックのスペクトルは測っていません。ペダルを踏んだときの共鳴（共鳴弦）はモデル化していません。音量の一致は、ハンマーや駒ではなく、滑らかにしたゲイン曲線によるものです。これらの測定は録音との類似度を表すもので、好みではありません。耳で確かめてください。

## 再現

```powershell
cargo build --release -p auris-synth --example physical_fit_render --features piano-calibration
uv run tools/eval/piano_register.py target/piano-register/references prepare
uv run tools/eval/grand_piano.py target/piano-grand/references prepare
uv run tools/eval/piano_register.py target/piano-register/references fit `
  target/release/examples/physical_fit_render.exe start.json fit.json --stages decay,spectrum,knock
uv run tools/eval/piano_register.py target/piano-register/references fit `
  target/release/examples/physical_fit_render.exe fit-voicing.json mel.json --stages mel `
  --grand target/piano-grand/references
uv run tools/eval/piano_register.py target/piano-register/references evaluate `
  before-renderer.exe target/release/examples/physical_fit_render.exe evaluation.json
uv run tools/eval/grand_piano.py target/piano-grand/references evaluate `
  before-renderer.exe target/release/examples/physical_fit_render.exe validation.json
uv run --with pytest --with numpy --with scipy --with soundfile pytest tools/eval/test_piano_register.py
```

開始ファイルは JSON の `PianoVoicing` で、キーは `piano-register-fit.json` の `voicing` と同じです。アンダースコアで始まるキーは楽器のパラメーターを設定します。変更前のワーカーをベースラインとして残しておいてください。ダウンロードした録音は `target/` に置きます。
