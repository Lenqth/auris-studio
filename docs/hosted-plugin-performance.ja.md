# ホストプラグインの再生パフォーマンス

[English](hosted-plugin-performance.md)

CLAP ホストは、アクティブなパラメータ表示をアトミックなスナップショットに保持します。Auris が書き込むオートメーションと、プラグインが出力するグローバルなパラメータ値イベントは、オーディオ側でそのスナップショットを更新します。この処理でメモリ確保やロック取得は行いません。プリセットの値はアクティブ化する前に読み込み、明示的な値の再スキャンと変更通知でセッションスレッド上のスナップショットを更新します。パラメータパネルを描画しても、アクティブなプラグインの値は問い合わせません。保存時には、引き続きプラグインの正規の状態を読み取ります。

これは、DSP とパラメータ取得を同じロックで保護するプラグインに関係します。メインスレッドから問い合わせると、プロセスブロックを待たされることがあります。また、オーディオコールバックで try-lock を使うプラグインでは、ゲッターがそのロックを保持している間に無音のブロックを出力する場合があります。

## 再現と計測

Auris と選択したプラグインを、どちらも Release モードでビルドします。結果を記録する前に、ビルドやほかの負荷の大きい処理を停止します。プロファイリング用の example は、オーディオデバイスを使わず、一定のペースで動くオーディオスレッドとパラメータパネルの同時読み取りを使います。

```sh
cargo build --release -p auris-clap --example profile_playback
target/release/examples/profile_playback /path/to/AmiSynth.clap 128 10 mixed
target/release/examples/profile_playback /path/to/AmiSynth.clap 512 10 mixed
```

Windows では `.exe` ファイルを使います。引数は、選択した CLAP ファイル、ブロックサイズ、秒単位の長さ、そして各楽器のコピー数（1〜16）またはライブラリ内の各楽器を同時に1つずつ再生する `mixed` です。各楽器には同じ4つのホールドノートを送ります。条件は、`closed`（パネルへの問い合わせなし）、`direct`（従来のテーブル全体を取得する方式）、`cached`（アクティブな表示スナップショット）の3つです。

出力には、プロセスブロックの p99 と最大時間、オーディオ期限を超えたブロック数、パネル問い合わせの p99 と最大時間、無音ブロック数、出力エネルギーの合計、PCM チェックサムが含まれます。決定論的なプリセットでは、エネルギーだけでなくチェックサムも `closed` と比較します。時間の計測対象は楽器の処理で、チェックサムとエネルギーの計算は含みません。48 kHz では、期限は128フレームで約2.67 ms、512フレームで約10.67 msです。複数の楽器が1つのコールバックを共有する場合は、ブロック時間の合計を比較します。CPU 使用率だけでは、1回のコールバックが期限内に収まるか分かりません。

無音ブロックは、特にドラムなど、減衰するプリセットの自然な終端になる場合もあります。同じフレーズと出力エネルギーを `closed` と比較し、無音ブロックをすべてアンダーランだと解釈しないでください。このツールはホストとパラメータの競合を調べるための専用プローブであり、実際のプロジェクト、デバイスドライバー、温度状態、電源モードのテストの代わりにはなりません。デスクトップ全体を再現するものでもありません。

## AmiSynth の調査

初期調査では、AmiSynth のコミット [`857f796`](https://github.com/Lenqth/AmiSynth/tree/857f796af43683d4a0a2507d359806c6c5c2bf1d) を MSVC の Release モードでビルドしました。CLAP の process 関数は try-lock を使い、パラメータゲッターは同じミューテックスを取得します。直接問い合わせる実行では Synth のオーディオブロックがスキップされることを再現でき、キャッシュした読み取りでは再生中にこのゲッターへ入らなくなりました。元の報告では、Ryzen 5800H のノートパソコンで複数の楽器、短い UI の停止、オーディオの中断が記録されています。開発マシンでの計測から、そのノートパソコンでサポートできるトラック数は分かりません。残る中断を CPU 容量に帰する前に、実際のプロジェクト、プリセットのバージョン、サンプルレート、バッファサイズ、電源モード、デバイスドライバーを再確認してください。
