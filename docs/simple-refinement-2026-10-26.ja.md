# 作曲ハーネスの単純化と実走結果

2026-10-26。流れを「作曲 → 評価 → 必要なら一度だけ局所修正」に変更した。
事前に複数の修正案を列挙する必要をなくし、評価後にエージェントが楽譜と歌詞を
確認して、修正の理由・期待する効果・失う可能性のある表現を説明する。
根拠がなければ、そのまま初稿を残す。

## 変更した運用

- 修正は一つの主旋律クリップ、一つのテーマまで。既定の変更上限は16音。
- 通常はフルミックスだけを出力。主旋律・伴奏の個別試聴は `--auditions` で追加する。
- 実際の音符差分がゼロなら、二度目の歌声合成・レンダー・SongEvalを省略する。
- 実行ファイル、モデル、歌声などの環境設定は共通の設定ファイルにまとめる。
- 修正に失敗しても初稿の音源を残す。失敗は終了コードとレポートで通知する。
- 点数が上がっても自動採用しない。修正した場合は両方の音源と編集可能な楽譜を残す。

歌詞、伴奏、音色、音量、曲構成などの保護は継続する。通常経路ではプロジェクトの
比較で保護を確認し、伴奏音声のハッシュ比較は個別試聴を出力した場合に行う。
[使い方と設定](composition-refinement.md)に新しいレシピ形式を記載した。

## 実走

伴奏と歌詞を固定した24小節のポップ歌ものを使用した。
112 BPM、4/4、C major、VOICEVOX 0.26.0のずんだもん／ノーマル。
音源は約51.43秒、48 kHz、ステレオ。処理時間は約10分34秒だった。
異なる条件の旧実験との速度比較は行っていない。

初稿では81音中79音の音高・タイミング等を変更した。その後のレビューは
**KEEP（修正なし）**を選び、変更は0音・0クリップだった。
フルミックスのレンダーとSongEvalは各1回だけで終了した。
修正版の音源と点数は存在せず、初稿を複製して比較用音源とはしていない。

| SongEvalの予測軸 | 初稿 |
| --- | ---: |
| Coherence | 3.5502 |
| Musicality | 3.1129 |
| Memorability | 3.4590 |
| Clarity | 3.3555 |
| Naturalness | 2.9854 |

レビューは、8分・8分・4分のモチーフとサビでの高音域への展開を維持した。
「朝」に入るG4→E5の跳躍を小さくする案も検討したが、歌詞に合わせた頂点を弱める
可能性があるため見送った。これはエージェントによる楽譜上の判断であり、直接の
聴取や歌いやすさの実証ではない。今回確認したのは、理由のない修正をしない経路の
動作であり、楽曲の改善や人間の好みとの一致ではない。

## 検証と記録

Pythonの関連テスト48件、ruff、スキル検証を通過した。実走で確認したのは
修正なしの経路。候補の作成、変更範囲違反、合成失敗時の初稿保持、点数が全軸で
上がっても自動採用しないことはテストで確認した。

実走後、レビューの定型文に初稿も「合成・評価待ち」と読める表現があることに
気づき、初稿の評価は完了済みと伝える文に修正した。この文言変更は回帰テストで
確認しており、実走の元スクリプトと発言記録は書き換えていない。

[機械可読の結果](../tools/eval/references/simple-refinement-2026-10-26.json)には
モデル・音源・実行時スクリプトのハッシュと実行環境の出典を記録した。
エージェントパネルとレンダラーは既存の固定済み実行ファイルを使用し、今回の
チェックアウトからビルドしたものとは区別している。

音源、楽譜、判断記録はローカルの
`~/Music/Auris Studio/Simple Refinement 2026-10-26` に保存した。
WAVは単独で試聴できる。再編集・再合成には既存の音源ライブラリと歌声環境が必要。
