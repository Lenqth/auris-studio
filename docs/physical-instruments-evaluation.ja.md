# 物理楽器の測定

[English](physical-instruments-evaluation.md)

2026-10-01、Windows、48 kHz で測定しました。比較ビルドはコミット `64ca54ee60b4105df336e46b53512b5c7d07334d`、候補は物理楽器の初期実装 `aaf5a0f` です。初期実装の説明は [physical instruments](physical-instruments.ja.md) にあります。その後のボディ、ギター、ピアノ、バイオリンの変更は [改良の記録](physical-model-refinement.ja.md) で別途測定しています。

<a id="conditions"></a>
## 条件

シンボリックルーラー（`cargo run -p auris-compose --example measure`）は、プリセットごとに8つのシードを使った変更前後で同一の出力を生成しました。スコア書き出しアルゴリズムは変更していません。

`tools/eval/aesthetics.py --preset all` は、通常のセッションバランス、32-bit WAV 出力、レンダー末尾なしで、9つすべてのプリセットを各デフォルトシードでレンダーしました。Audiobox Aesthetics は完全なレンダーを採点しています。これらは単一シードによる診断結果であり、聴取テストの結果でも、品質が同等である証拠でもありません。CE は予測コンテンツ楽しさ、PQ は予測プロダクション品質です。どちらも1〜10の尺度です。その他の軸は CU（コンテンツの有用性）と PC（プロダクションの複雑さ。高いほど本質的に良いわけではありません）です。

サポートする楽器ファミリーの変更とアセットの削除を区別するため、次の3条件を使います。

* **Old + GM:** MuseScore General を使う比較ビルド。
* **New + GM:** サポート対象のヒントにはネイティブモデルを使い、その他のヒントには同じオプションの GM フォントを使う候補。
* **New native:** `AURIS_SOUNDFONTS` を空のディレクトリに向けた候補。

フォントは 215,614,036 バイトで、SHA-256 は `ee51d2c4b1525e70f19a45909c4fd7a2e26d91d115fa89dbf5a6bc413d8b9bf3` であることを確認しました。オプションでインストールしたフォントは、フルート、金管、シンセパッドなどサポートされていないファミリーを補います。フォントがない場合、セッションは報告済みのシンセサイザーフォールバックを使います。そのため、これらの条件には、既存のドラムキットがフォントのドラムプリセットを置き換えることと、新しいレベルバランスも含まれます。

<a id="reproduction"></a>
## 再現

上の表は過去の Audiobox 測定値を保持しています。現在の再実行では TuneJury と MuQ-MuLan を使うため、そのスコアは表の値と比較できません。

古い CLI 実行ファイルと新しい CLI 実行ファイルは別々に保存してください。最初の2条件では `AURIS_SOUNDFONTS` を同じ検証済みフォントディレクトリに向け、3つ目では空のディレクトリに向けます。

```sh
uv run tools/eval/music.py --preset all --cli /path/to/old/auris --workdir before --json before.json
uv run tools/eval/music.py --preset all --cli /path/to/new/auris --workdir after --baseline before.json --json after.json
```

数値 DSP とセッションのテストでは、ピッチ、ベロシティ、モーダルな明るさ、減衰、ペダル、エクスプレッション、ベンド、ライブダンピング、コールバックの無割り当て、明示的なパラメーター優先順位、Undo、保存／開く、再オープン後の PCM 一致も対象にしています。`physical_demo` は6モデルによる別の聴取プローブを書き出します。リリースアーカイブには標準フォントアセットを含めません。アーカイブ圧縮率と最終実行ファイルサイズの差は、この実験では測定していません。
