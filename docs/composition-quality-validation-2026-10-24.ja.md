# 作曲ハーネス検証 — 2026-10-24

[English](composition-quality-validation-2026-10-24.md)

このレポートは、本番記録、不変の作曲候補、範囲を限定したフレーズ／終止の変化、タスク別プロンプト、バックエンド横断評価を扱います。エンジニアリング上の正しさ、配信、音楽的好みを分けています。候補カタログとモジュール式プロンプトは実験的なままで、人による選好評価は集めていません。

<a id="conditions-and-retained-evidence"></a>
## 条件と保持した証拠

3つの実験は目的が異なります。

* Runtime smoke は、1つの正確な音高変更、編集なしのプレビュー、次ターンでの採用、Undo/Redo、16秒の24-bit WAV/MIDI 配信を要求します。Codex は `gpt-6.1-sol`、Claude Code は `sonnet`、Rig はローカルの `qwen3.8:27b` を使います。モデルが異なるため、バックエンド品質の順位ではありません。
* プロンプトアブレーションは開発ケース1件（`loop_title`）、条件ごとに3試行、固定バイナリ1つ、同一ツールカタログを使います。旧指示と初期モジュール式プロファイルを比較します。後の保留候補指示の修正は別に評価し、このコホートには置き換えません。
* ホールドアウトは4つすべての保留ケース、条件ごとに3試行、変更しない v1 マニフェスト、Codex `gpt-6.1-sol` を使います。ベースラインは固定 phase-3 runtime、新条件は旧プロンプト付き phases 4–6 です。新条件の4ケースのシャードは並行実行します。失敗した試行もコホートから除外せず、経過時間は性能ベンチマークではありません。後の修正はモジュール式指示だけを変更し、評価済み旧条件は変えません。

すべてのスイートは、ソース出所、実行ファイル／DLL ハッシュ、設定、トランスクリプト、ドキュメントスナップショット、エンコード測定、アーティファクトハッシュを `target/quality-final` に保持します。バイナリを再利用すると、現在のチェックアウトに帰属させず、元のスイートのランタイムハッシュを検証します。ローカル証拠ディレクトリは Git から無視され、[数値レポート](../tools/eval/references/composition-quality-validation-2026-10-24.json)にはスイートハッシュ、実行ファイルハッシュ、プロジェクトスナップショットハッシュ、監査概要があります。ランタイムマニフェストのハッシュはソート済みコンパクト JSON を使い、元のスイートには全 DLL ハッシュを残します。

24件すべての配信は要求長から1サンプル以内で、フルスケールサンプルは0です。最終ドキュメントはすべて要求されたテンポと拍子に一致します。6件の folk 試行すべてで、コントローラーデータ、元のテンポ／拍子マップを含む元メロディークリップ全体を保持しました。外部クリティック呼び出しはありません。失敗呼び出しの合計は30から37に増えましたが、全試行は回復して配信しました。これは信頼性や音楽的好みの改善を示しません。評価済み旧条件の調整にホールドアウト出力は使っていません。

<a id="exact-edit-runtime-checks"></a>
## 正確な編集のランタイム検査

修正済みフィクスチャの Claude 試行は、ツールエラーなしで完全な契約に合格しました。最初の Codex 試行はトランスポートを完了してファイルを書きましたが、保留ラウンドをキャンセルしたため編集契約に失敗しました。指示修正後の別 Codex 試行はツールエラー0で合格しました。成功した両配信には要求どおりのドキュメント変更があり、エンコード WAV SHA-256 は同じ `481fcfd4d386180f27c4c7a85b9683d7cbae9a649acea75e507efc614db2b7db` でした。これは正確な編集を示すもので、好みの改善や任意リクエストの成功率ではありません。

ローカル Rig 試行も、設定コンテキストトークン131,072で完全な契約に合格しました。回復したスキーマエラーは、操作タグ欠落、タグなしレンダー先、未対応の本番記録操作の3つです。最終ドキュメントと WAV ハッシュは CLI の成功試行と一致します。このマシンでは2,287秒かかり、Ollama は CPU／GPU の部分オフロードを報告しました。最終報告の入力コンテキストは3回のやり取りで25,319、27,624、27,949トークン、会話出力の報告合計は16,629トークンでした。最後の値はピークでも累積入力使用量でもありません。64k ガード失敗は**推定**であり、実際に64k超を必要とした証拠ではありません。大きな割り当てを修正と扱う前に、その保守的なガードをプロファイルしてください。

修正後の Codex 実行は、コントローラー曲線読み取り261回を含む347ツール呼び出し、Claude は30回でした。個々のコントローラーレーンを網羅的に再読することは、観測された効率問題です。将来の一括保持レポートで、正確な内容検査を弱めずにコストを下げる必要があります。モデル名とバックエンド条件が異なるため、これらの数は一般的なモデル順位を示しません。

<a id="findings-that-changed-the-implementation"></a>
## 実装を変えた知見

最初の Codex smoke は本番記録キーにドットを使いました。安全な識別子ですがバリデーターが拒否し、スキーマにも制限が公開されていませんでした。現在はドットを受け付け、スキーマがパターンと長さを宣言します。置換、保持、スラッシュを含むキーの原子的拒否を回帰テストで検査します。元の2つの失敗は診断試行に残ります。

ソース参照ハッシュは、試行結果を追加できるスイートを最初は指していました。ランナーは参照バイトを一度読み、変更不能な `source-suite.json` を保存します。回帰テストは元ファイルを更新し、スナップショットが記録済みハッシュと一致することを確認します。完了済み実行では、変更されていない出所と試行プレフィックスから正確な参照スナップショットを復元し、全バイト列が以前の SHA-256 と一致することを要求しました。ソースハッシュや試行結果を合わせるために書き換えてはいません。

Smoke v1 は評価フィクスチャの誤りも明らかにしました。シードが1拍480ティックを使い、Auris の960と違うため、要求8小節ではなく4小節でした。Codex は書き出しの前に確認を求め、Claude は実際の8秒シードを書き出して不一致を開示しました。どちらも有効な8小節配信テストではありません。Smoke v2 は回帰テスト付きのバージョン管理された8小節フィクスチャを使います。元の v1 シードはホールドアウト比較の両側で変更しません。

最初の修正済みフィクスチャの Codex 試行では、採用またはキャンセルするモジュール式指示により、次ターンで採用してほしい候補をエージェントがキャンセルしました。ホストはキャンセルされたラウンドを正しく拒否し、ドキュメントを保持しました。ファイル配信は成功し、トランスポートとファイル存在だけでは要求された編集の代わりにならないことを示しました。共通プロンプトは現在、延期した候補を保持し、ターンを終えるためだけにキャンセルすることを禁じます。別試行で修正を評価し、失敗試行も残します。

最初のローカル Rig 試行は候補作成と検査後に65,536トークン予算へ到達しました。予算ガードがスコアを変更せず停止しました。別の131,072トークン実験はモデルが対応するコンテキスト範囲を使います。アプリケーションのデフォルトは変更しません。コンテキストを大きくしたことだけでは品質を主張しません。

<a id="validation-and-adoption-gate"></a>
## 検証と採用ゲート

最終2回の回帰前に、doctest を含む4,516件の Rust テストが通過し、追加した2回の回帰も通過しました。変更後にワークスペース Clippy とフォーマットも通過しました。評価器とクリティックのスクリプトは12 pytest テストと Ruff に合格しました。候補テストは、正確な適用、Undo 1回、冪等リトライ、保護内容、キャンセル、古い／別／期限切れラウンド、予算、プレビュー公開、実際にエンコードしたプレビューファイルの測定を対象にします。

本番記録は、帰属コンテキストをツール所有の観測とは別に保存します。テストは再開、リセット競合、ID欠落、出力上限、リビジョン無効化（編集後の Undo を含む）を対象にします。保存プロジェクトの候補往復とライブワーカー契約は、実推論とは独立して検査します。

これらのチェックはより良い音楽を示しません。デフォルトプロンプトを変更する前に、人によるブラインド評価、リクエスト適合度、ケースごとの失敗が必要です。ローカルコンテキスト枯渇と不要な検証呼び出しは、ホールドアウト出力に対して調整せず、今後対処すべき運用上の制限です。
