# VOICEVOX 発音チェック

[English](voicevox-pronunciation.md)

2026-10-22 の調査では VOICEVOX Engine 0.25.2、予測スタイル6000、アダプターの93.75 fpsクロックを使いました。基準コミットは `8025e4ab` です。

発音には次の3つのアダプター問題がありました。

- 拡張かなが通常の音節に分割されていました。たとえば `スィ` が `s i` ではなく `s u i` に、`クォ` が `kw o` ではなく `k u o` になっていました。かなリーダーは不足していた拡張モーラと Engine の別名を認識するようになりました。187通りの綴りのうち、基準リーダーが40通りを余分な音節に分け、`ヶ` を認識しませんでしたが、41通りすべてを修正しました。
- 予測された子音が直前のノート内で母音に先行することがあります。直前のノートのゲインを適用すると到来する子音が消え、ピッチ編集を適用すると子音の音高も誤ることがありました。予測された発音範囲は、現在そのノート自身のコントロールを使います。
- 短いノートの母音にフレームが0個割り当てられたり、一時的な問い合わせフレームが後続子音から削除されたりしました。アダプターは母音フレームを1つ確保し、母音の開始位置と全体の長さを変えずに音響曲線を再計算します。子音の直前にある1フレームのノートは、このグリッド上で両方の音を保持できないため、歌詞の長さエラーとして報告します。

<a id="inventory-measurement"></a>
## インベントリ測定

個別問い合わせのスイープでは、MIDI 60で163個の主モーラ綴りを対象にしました。対象モーラは24フレームで `ア` の後に置き、前のノート長と間隔を下表のように変えました。両境界には94フレームのパディングがあります。

| 前のノート | 間隔 | ケース | 基準の音素不一致 | 修正後の不一致 | 長さエラー |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 24 | 0 | 163 | 35 | 0 | 0 |
| 24 | 2 | 163 | 35 | 0 | 0 |
| 24 | 8 | 163 | 35 | 0 | 0 |
| 4 | 0 | 163 | 68 | 0 | 0 |
| 2 | 0 | 163 | 36 | 0 | 0 |
| 1 | 0 | 163 | 156 | 0 | 156 |

表現可能な822ケースすべてで、Engine が意図した非休符音素列を保持しました。残りの156件は推論前に拒否されます。35件の誤分割、条件、Engine バージョン、インベントリのソースハッシュを [測定結果](../tools/eval/references/voicevox-pronunciation.json) に収録しています。

回帰テストでは別名を含む187綴りすべてをバッチスコアでも対象にし、Auris のかなパーサーとは独立して Engine に直接送った問い合わせと5つのタイミング条件を比較します。歌われる各音素は正の長さを持たなければなりません。187綴りすべてで1フレーム長の検証も行います。

これらの検査が測るのは音素の保持であり、すべての歌い手と音高での聞き取りやすさではありません。四国めたん / ノーマルとの音声プローブでは、Engine の音素と予測曲線を同一に保ち、コントロールの所有者だけを変更します。ゼロベロシティのノート後も到来する `/k/` と `/s/` は聞こえ続けます。予測子音区間の波形 RMS はそれぞれ約20 dB、22 dB上がり、両版で到来ノートの意図したベロシティは0.8です。数値テストでは、到来側のピッチ編集が使われ、直前の母音が自身のゲインを保つことも確認します。

<a id="velocity-and-the-engines-volume"></a>
## ベロシティと Engine の音量

2026-10-23 の調査では Whisper（large-v3-turbo）で歌声プローブを文字起こししました。Engine の `volume` はフェーダーではなくデコーダー入力です。レベルを正規化しても、値を変えるとすべての音素のスペクトルが変わります。四国めたん / ノーマルが歌う24フレーズでは、音素ごとの対数スペクトル RMS 差は ×0.8 で約0.5、×0.5 で0.9、×0.3 で1.2でした。Auris は以前、velocity × expression をこの倍率として送っていました。ベロシティ0.5では、四国めたんと波音リツの文字誤り率が約10%から18.7%に上がり、誤りは ば→ま、ざ→だ、ひ→ぎという子音置換でした。

アダプターは予測した volume を変更せずに送り、velocity × expression をデコード済み音声へ適用するようになりました。ゲインはフレーム中心間で補間します。母音に先行する子音も自身のノートのゲインを使います。

変更を分離する同一テイク比較では、四国めたん / ノーマルの24フレーズ×3テイク、計72問い合わせを使い、volume を縮小した場合と音声を縮小した場合を比較しました。

| レベル | volume 縮小（変更前） | 音声縮小（現在） |
| ---: | ---: | ---: |
| 0.8 | 11.9 % | 11.4 % |
| 0.5 | 19.0 % | 11.7 % |

0.5では音声縮小が20テイクで良く、8テイクで悪くなりました。除去された誤りは子音置換（さしすせそが しじせぞ、ざじずぜぞが ざみでぞ、ぽすとが ぼすと）です。残る誤り率は最大音量時と同じです。

Engine 0.25.2 には比較を制限する性質が2つあります。`sing_frame_audio_query` は音素長を決定論的に予測しますが、f0 と volume はリクエストごとに変わるため、同じスコアを2回レンダリングしても別のテイクになります。そのため公平な比較では同じ問い合わせを2回合成します。`frame_synthesis` は決定論的です。Auris がなくても混同は起こり、Engine へ直接歌わせた多くのテイクで ぱ行が ば行に聞こえました。

<a id="reproduction"></a>
## 再現手順

Engine を起動し、`AURIS_VOICEVOX_TEST_URL` に URL を設定して次を実行します。

```sh
cargo test -p auris-vocal
cargo test -p auris-singer
```

ライブインベントリ回帰テストは `a_running_engine_preserves_the_mora_inventory_across_timing_adaptation` です。環境変数がない場合、Engine に接続せずに Engine 依存テストを終了します。既存の保存済みテイクには明示的な再レンダリングが必要です。

聞き取りやすさを確認するには、プローブをレンダリングして文字起こしします。

```sh
cargo run -p auris-singer --example voicevox_probe -- target/voicevox-probe 3002
uv run tools/eval/voicevox_intelligibility.py target/voicevox-probe
```

プローブは各フレーズをAurisで3つのベロシティで、さらにEngineへ直接1回通します。スクリプトは書かれたかなを基準に、各バリエーションの文字誤り率を報告します。
