# ライブパフォーマンス編集の検証

[English](agent-performance-validation.md)

2026年10月22日、組み込みのCodexとClaude Codeのバックエンドは、アプリケーションのエージェントパネルを通じて、独立した読み戻し、オーディオレンダリング、そしてUndo/Redoチェックを含む実際のパフォーマンス編集を完了しました。Claudeの成功したトライアルは、ユーザーが期限切れのOAuthセッションを更新した後に行われました。

<a id="scope-and-results"></a>
## 範囲と結果

オプトインGPUIテストは、隔離された構成、保存されていない生成クリップ、作成されたベンド/ボリュームカーブを備えた実際のアプリケーションを開きます。実際のエージェントワーカー、ネイティブCLI、埋め込みMCP、アプリケーション権限、セッション、レンダラーを使用します。ハーネスはディスプレイ、GPU、オーディオデバイスを必要としません。デフォルトのEditポリシーが適用され、承認の回避はありません。既存のユーザープロジェクトは変更されません。

バックエンドの両方で同じ日本語のリクエストが受信されました。クリップを検査し、`set_performance`の1回の呼び出しで6つのパフォーマンスコントロールを変更し、他の設定とソースデータを保持し、その結果の設定を検査することです。

| バックエンド | 結果 | 証拠 |
| --- | --- | --- |
| Codex CLI 0.163.0、`gpt-6.1-sol` | 25.00秒で通過しました | 読み取り/編集/再生完了；1回の成功した編集；スコアとカーブは保持された；UndoとRedoは完全なプロジェクトを復元した |
| クロスドコード2.1.304、`sonnet` | 再認証後9.44秒で通過しました | 読み取り/編集/再生完了；1回の成功した編集；スコアとカーブは保持された；UndoとRedoは完全なプロジェクトを復元した |

両方とも、16分音符に適用されたスイングを62％、ゲートを0.5、トランスポーズを+12半音符、表現速度変動を0.3、ストラムスプレッドを30ms、ビブラート深度を0.2半音符に設定しました。読み戻しは6つのコントロールすべてに一致しました。表現タイミング、スウェル、グループおよびシード、ストラム方向、そして作成された自動ボリュームコントラストは保持されました。インスペクターの組み合わせた`humanize`値も、表現タイミングと速度の最大値を示すため0.3に上昇しました。これは独立した設定ではありません。

ホストは各編集前の各編集後の2秒間のステレオレンダーを同じようにレンダリングしました。各バックエンドは同じ最終ドキュメントとレンダリング測定値を出力しました。両方の96,000フレームのレンダリングは聴覚的に確認でき、サンプルピークは0.167717と0.202802でした。サンプル差のRMSは0.0377444でした。これは音楽品質に対する人間の判断ではなく、実際のレンダリングされたオーディオの変化を確認しています。Codexは、アプリケーション説明書が要求しているため、`inspect_audio`と呼びました。

<a id="earlier-claude-attempts"></a>
### 以前のクロスドの試み

最初のClaudeの試行は、`OAuth session expired and could not be refreshed`のツール呼び出しが行われる前に停止しました。再認証後、最初の編集は6つの要求された値すべてを適用し、ソース、音声、Undo/Redoチェックに合格しましたが、個別のポストエディット`inspect_performance`呼び出しは省略されていました。その試行は独立した再生基準に失敗し、証拠には`readback_missing`として記録されています。

このハブは、エージェントがその検査なしで編集後に終了した場合、同じ会話内で1回の明示的な読み取り専用のフォローアップを許可します。それでも、別々の成功した検査、正確な値、1回の編集、そして元の数値および保存チェックが必要です。最終的に成功したClaudeの試行にはフォローアップは必要ありませんでした；両方の成功したバックエンドは最初のターンで全シーケンスを完了しました。

コンパクトな証拠は[`agent-performance-2026-10-22.json`](../tools/eval/references/agent-performance-2026-10-22.json)です。完全なトランスクリプトと前後のドキュメントスナップショットは、無視されたローカルの`target/eval/performance-live-2026-10-22`ディレクトリに保存されています。

<a id="reproduction"></a>
## 複製

選択したCLIをインストールし、認証します。`backend`（`codex`または`claude`）、`model`、`timeout_seconds: 180`、そして親ディレクトリが存在し、最終ディレクトリが新しい絶対的な`output`パスを含むUTF-8 JSON構成を作成します。`AURIS_PERFORMANCE_EVAL`を構成パスに設定し、次に実行します：

```powershell
cargo test --workspace installed_cli_edits_performance_in_the_window -- --ignored --nocapture --test-threads=1
```

これはサインイン済みのアカウントを使用して実際のモデル推論を実行します。テストではツール呼び出しの成功と、状態およびレンダリングの正確なチェックが必要です。認証およびプロバイダーの制限は引き続き失敗します。通常のテスト実行では、このオプトインテストはスキップされます。

<a id="articulation-selection-and-measured-effects"></a>
## アーティキュレーション選択と測定効果

別々の`installed_cli_selects_slide_or_glide_and_reports_effective_performance`評価では、APIプロパティを名付けることなく、音楽的なジェスチャーを要求します。ネイティブの物理的なギターとベース楽器で5つの短いクリップを使用します：

| クリップ | リクエストされたまたは既存のジェスチャー | 必要な証拠 |
| --- | --- | --- |
| ギターコード | 低から高のストローク | 開始時刻を変更し、音声をレンダリングした |
| ベースA | 短い中間ピッチ1つ | スライドノートを追加し、連続スライドを解除し、音声を変更しました。 |
| ベースB | スムーズな継続的な接続 | Glideの孤立した曲がり込みの貢献、変更されていないノートイベント、変更された音声 |
| ベースC | 既存のスライドが長い休符をまたぐ | 隙間により無効になるグライドが測定されました。音声は変更されていません。 |
| ベースD | 繰り返されるピッチ間の既存のスライド | 間隔の理由を記載した挿入ノートなし；音源は変更されません |

モデルは、編集前に各編集されたクリップを検査し、変更後も独立して検査する必要があります。以前の評価と同様に、モデルが別々のパフォーマンスの読み戻しなしで編集を完了した場合、同じ会話内で1回の明示的な読み取り専用フォローアップは許可されます。結果はそのリマインダーが必要だったかどうかを記録しますが、読み戻し、ソース保存、オーディオチェックを免除するものではありません。権限や承認リクエストは回避されません。無効なジェスチャーの証拠は、ハーネスの最終的な読み取りだけではなく、モデル自身の成功した検査結果に表示される必要があります。ハーネスは許可されたパフォーマンススタックのみを置き換えた後の完全なプロジェクトを比較し、Undo/Redoを完全な前後プロジェクトと比較します。作成されたベンディングとコントローラーカーブ、生成されたレシピはフィクスチャーに存在します。

上記のJSON構成フィールドと同じものを使用しますが、`AURIS_ARTICULATION_EVAL`を設定して実行します。

```powershell
cargo test -p auris-gpui --bins installed_cli_selects_slide_or_glide_and_reports_effective_performance -- --ignored --nocapture --test-threads=1
```

各実行は、新しい出力ディレクトリに`transcript.json`、`result.json`、および前後5つのWAVペアを保存します。オーディオRMS差は、これらのネイティブ楽器が応答していることを確認しますが、音楽的品質を測定したり、関連のないホストされたパッチのMIDIマッピングを確立したりするものではありません。ソース演奏者アルゴリズムは変更されていません。

Codexは、変更前後でローカルの`inspect_audio`を別途指定しました。Claudeはエンコード診断を使用し、報告書では楽器の応答を明示的に検証せずに記載しました。ハブは上記の上位のネイティブオーディオの違いを独立して特定しました。

以前の試行は最終通過としてカウントするのではなく、保留されています。Codexは当初、外部の`listen`からの批判を求め、編集前にアプリケーションの承認リクエストで停止しました。再実行では、検証を同じ許可ポリシーのローカル測定に明確に限定しました。Claudeの最初の試行は構造チェックに合格しましたが、残りの時間を500 msと誤って記載しました；テンポ由来のギャップ測定を追加することで、後の試行でその報告が修正されました。別のClaudeの試行ではすべてのジェスチャーを正しく選択しましたが、編集されたクリップに対する独立した演奏の読み戻しを省略したため、その基準に失敗しました。制限付きの読み取り専用リマインダーは、この省略を修正しましたが、主張を緩和することはありませんでした；最終の試行ではリマインダーなしで完了しました。
