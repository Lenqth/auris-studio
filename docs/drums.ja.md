# ドラムトラック

[English](drums.md)

ドラムには、メロディックなソフトウェア楽器とは別に、独自のトラックタイプがあります。内蔵キットで始めるにはドラムトラックを作成するか、そのトラックにサウンドフォントまたはホストされた楽器を選択してください。その音を変更しても、ドラムとしてのアイデンティティは維持されます。作曲したパーカッションやインポートされたMIDIチャンネル10パートはドラムトラックを使用します。古いプロジェクトは、保存されたノートとパフォーマンスを維持しながら、明示的なパーカッションメタデータを移行します。

<a id="physical-kit-and-motion-display"></a>
## フィジカルキットとモーションディスプレイ

内蔵キットは、スラップ、スネア、6つの調律されたトム用の打撃される円形膜、ハット、クラッシュ、ライド用の金属プレートの減衰する曲げモードを模倣しています。損失のあるキャビティが動くドラムヘッドに追随します。弾性のあるワイヤーと金属の衝突には、拡散ノイズエネルギーの近似を用います。ビーターの硬さと打撃位置によってモードエネルギーの分布が変わり、ダンピングと共鳴減衰はテールを変えます。共鳴減衰は各パッドの自然な持続時間を基準とします（デフォルトは100%です）。レベルパラメータは保存済みプロジェクトでも元の状態を保ちます。

キットの楽器エディタを開くと、傾斜した表面グリッド上の実際のモード変位と最初の8つのモード振幅が表示されます。最大4つの最近のヒットが別々に表示され、膜とプレートの幾何学がそれぞれ表示されます。Previous drum / Next drum を使用してパッドを選択し、Play を押して繰り返し打つことができます。GainとFreezeの表示は観察にのみ影響します。エディタを閉じると空間再構築は無効になり、オーディオレンダリングは変わりません。

<a id="editing-and-generation"></a>
## 編集と生成

ドラムクリップを開くと、ドラムエディタが表示されます。その行には、トラックの作成者が定義した割り当てと、クリップに存在するMIDIアドレスが使われます。ドラムクリップはドラムトラック間で移動して貼り付けられますが、メロディッククリップはメロディックまたはシンガートラックに残ります。

ドラム生成は、コード進行のない空のタイムライン上で動作します。フルキット、キック、スネア、ハイハットのプレセットは、選択した範囲の拍子とグルーヴを使用します。それらを生成または再生成しても、プロジェクトにコードが追加されることはありません。

生成されたドラムクリップには**ドラマー**インスペクターがあります。パフォーマンスパッドを右に移動すると複雑さが高まり、上に移動すると強度が高まります。ドラッグは元に戻せる編集であり、テイクのシードを保持します。グルーヴを選択したり、フィルの調整、スイング、ダイナミクスを調整したり、別のテイクを選択したりできます。独立したライターを備えたキットでは、各リズムボイスの複雑さ、強度、テイクも表示されます。1つのライターを編集しても、他の声とその保存された割り当ては保持されます。作成者が固定したリズムはそのリズムを保ちますが、強度は調整可能です。フリーズすると、現在のノートとドラムトラックは保持され、生成レシピは削除されます。

<a id="manual-programming-and-drum-maps"></a>
## 手動プログラミングとドラムマップ

ドラムエディタの左側は、名前付きレーンの順序付けられたマップです。レーンは**0から127**までの任意のMIDIノートを使用でき、手動レーンは自動ドラム生成で使用される6つのサウンドのいずれかである必要はありません。マップメニューまたはレーンのコンテキストメニューを使用して、レーンを追加、再命名、削除、または並べ替え、MIDIノートを変更するか、オプションの生成役割を割り当てることができます。有用な出発点となる場合は、General MIDIの完全なテンプレートを利用できます。ノート名を表示するCLAP楽器は、これらの名前を自動的に提供します。General MIDIパーカッションのSoundFontバンクは標準的な名前を使用します。

3つのビューボタンは、一般的な作業を区別します。

- **Map**は作成されたレーンの順序を維持し、クリップにすでに存在している未マップのノートも表示します。
- 「使用済み」は、現在のクリップで使用されているMIDIノートのみを表示します。
- **All 128**は、キットを探索またはマッピングする際にすべてのすべてのMIDIノートを表示します。

空のマップでは、General MIDI、保存済みマップ、MIDI Learn、新しい空白レーンを開始時の選択肢として提示します。MIDI Learnは、Musical Typingで演奏される次のノート、または**All 128**でクリックされる次の行を受け付けます。レーン名をダブルクリックすると名前を変更できます。固定幅の列が切り取る場合でも、そのフルネームはツールチップにも表示されます。

空のグリッドセルをクリックまたはドラッグすると、現在のグリッド間隔のヒットが表示されます。これにより、1回のストロークで繰り返されるパターンを書き込むことができます。既存のヒットをドラッグして移動できます。消去修飾子は消去ストロークを表示しますが、既存の選択、速度、キーボードコマンドは引き続き使用できます。各ストローク、レーンの再順序付け、またはマッピングコマンドは、1回の元に戻せる編集です。

レーンのMIDIノートを変更するには、2つの明示的な形式があります。**マッピングのみ**は、スコアを操作することなく、今後の入力と生成のアドレスを変更します。**既存のヒットを移動**も、レーンの古いノート上のすべてのヒットを再割り当てします。レーンを削除しても、そのヒットは削除されず、マッピングされていないMIDI行として表示され続けます。

すべてのマッピング編集は、正確なサウンドソース（内蔵楽器、ホストされたプラグインファイル、またはSoundFontファイル、バンク、パッチ）に対して自動的に保存されます。後で新しいトラックまたはソースを選択すると、設定を繰り返すことなくそのマップが復元されます。ユーザーレベルのライブラリは便利ですが、完全な順序のマップはプロジェクトにも埋め込まれているため、プロジェクトを別のコンピュータに移動しても名前、順序、役割の選択は保持されます。

6つのインスペクター割り当ては自動生成のショートカットとして残っています：キック、スネア、クローズドハット、オープンハット、クラッシュ、トム。1つを変更またはクリアすると、対応するオプションレーンロールが更新されます。これらは音楽的な選択であり、サウンド分析が完了する前に編集できます。既存のノートやクリップレシピは変更されず、既存のレシピは再生時に保存された割り当てを保持します。クリアされたロールは新しいクリップには割り当てられておらず、ジェネレータは従来のMIDI番号で代用しません。

<a id="drum-sound-measurement"></a>
## ドラム音の測定

ドラムトラックが作成または読み込まれると、デスクトップはバックグラウンドのドラムサウンドを自動的に分析し、楽器、プリセット、またはパラメータが変更された後も新しいサウンドを分析します。各トラックは独自の分析状態と結果を保持します。トラックを選択し、**Analysis → Drum Sound Analysis…** を開くと、分析がキューに登録されているか、実行中か、完了しているか、キャンセルされているか、または失敗しているかを確認できます。保留中の分析をキャンセルしたり、失敗後に再試行したり、トラックのコンテキストメニューから **Rescan Drum Sounds** を選択したりできます。変更されていないソースは繰り返しスキャンされません。キャンセルまたは失敗した分析は、再試行またはソースの変更を待機します。

作業者は各MIDIキーを3つの速度で2回ずつトリガーし、その結果となるステレオオーディオを測定します。内蔵楽器、明示的に選択されたSoundFontプリセット、状態を持つホストされたCLAPまたはVST3楽器は、同じ分析を使用します。分析パネルには、提案された役割、数値化された適合度、スペクトル重心、エネルギー持続時間が表示されます。

結果を適用することは、別々の明示的な操作です。**新しいクリップのみにマッピングを使用**は、空または部分的な割り当てを含む提案を将来の生成用に保存します。**測定ドラムマッピングを使用**は、既存の生成されたドラムノートとそのレシピを、1回の元に戻せる編集として再割り当てします。

分析自体はプロジェクトを編集しません。選択された楽器の現在の状態は、その所有元のスレッドにスナップショットとして保存され、その後、独立したワーカープロセスで復元されます。ワーカーはトラックインサート、センド、ミキサーゲインを行う前に、楽器を直接レンダリングします。親プロセスはスキャンをキャンセルするか、期限で終了させることができます。ソースが測定以降に変更された場合、結果は拒否されます。ドキュメントを置き換えるか再読み込むと、その保留中の分析がキャンセルされ、以前の結果をクリアします。自動分析は、作成者による割り当て、クリップレシピ、保存されたノートを保持します。

コマンドラインは同じ操作を提供します。

```sh
auris analyze-drums /path/to/Song.auris --track Drums
auris analyze-drums /path/to/Song.auris --track id:5 --first-note 0 --last-note 127 --apply
auris analyze-drums /path/to/Song.auris --track Drums --apply --remap-clips
```

最初のコマンドはJSONレポートを出力します。`--apply`は計算されたマップを将来の生成用に保存し、`--remap-clips`は保存前にチェックポイントを設定したうえで、既存の生成されたドラムノートも再割り当てできます。手動で作成されたタグ付けされていないノートはピッチを保持します。スキャンで見つからない役割が必要な生成されたボイスがある場合、ドキュメントを変更せずに再マッピングが失敗します。MCPとエージェントは同じオプションで`analyze_drum_kit`を公開します。そのデフォルトレポートは各可聴ノートの測定範囲を要約し、`include_triggers`はすべての記録されたトリガーを返します。`inspect_composition`は個別のドラムライターを報告し、`edit_recipe`は`drum_voice`を受け取り、あるライターの音楽制御を変更します。

MCPとエージェントはまた、`set_drum_assignment`を提供します。割り当てを追加または変更するにはプロジェクト、ドラムトラック、ロール、`note`を提供し、クリアするには`remove: true`を提供してください。各実際の変更はチェックポイントを保存し、既存のクリップを保持します。

<a id="evidence-and-assignment"></a>
## 証拠と課題

DSP分類器はPCMとそのサンプルレートのみを受信します。MIDIアドレスはどのキーがトリガーされたかを識別しますが、ノート名、一般MIDI割り当て、楽器名、サンプルラベルは計算には含まれません。作成されたドラムマップは、これらの測定値とは独立して音楽的な選択を記録します。

チャンネルのパワーは別々に測定され、反対位相ステレオ音を保持します。測定にはピークとRMSレベル、オンセット遅延、捕獲エネルギーの90%までの時間、持続エネルギー、そしてアタック、ボディ、テールのウィンドウ化スペクトルが含まれます。スペクトル特徴にはバンドエネルギー、重心、平坦度、ピーク濃度、低周波スペクトルピークの動きが含まれます。

明示的なアコースティック基準は、キック、スネア、クローズドハット、オープンハット、クラッシュ、トムの6つの独立した適合度スコアを生成します。これらは楽器の識別可能性の確率を示すものではなく、音楽的な役割に適しているかどうかを記述します。明るく長い音は複数の役割に適応できます。各ノートの合計スコアは、測定された速度と繰り返しの間で最も低いスコアです。レポートには、すべてのトリガーとそのバリエーションも記録されます。自動提案には最低適合度0.55が必要です。適格な音がない役割は割り当てられません。これらの基準は、名前ベースの事前知識を導入せずに評価し、修正できるエンジニアリング仮説です。

ノートは録音ウィンドウを通じて保持されるため、短いノートオフでは持続的なベースが打撃音のように聞こえることはありません。トリガーの間、ワーカーはボイスの再生を停止し、静寂を待機します。これにより、各ヒット前にソースをリセットするのではなく、ラウンドロビンバリエーションを維持します。落ち着かないテール、無効なPCM、利用できないステートリセット、または処理失敗はスキャンを無効にします。

<a id="score-and-rendering"></a>
## スコアとレンダリング

1つのキットトラックには、セクションごとに1つの楽器インスタンスと1つのクリップが含まれています。各ノートは安定したボイスタグを保持します。複合レシピは独立したライターと固定形式のアクセントを保持し、スコープされたパフォーマンストランスフォーメーションは各ボイスのタイミングと速度変動を保持します。全体キットの再生成と個別のボイスの再生成は、保存された割り当てを使用します。部分マップを受け入れると、新しいクリップが生成される際に、欠落した役割のサウンドが作成されません。

内蔵の`auris.synth.drumkit`には、準備済みのボイスプール、トーンキックとトム、ノイズの多いスネア、高域のハットとシンバル、共有されたオープン/クローズハットチッキングが搭載されています。レンダリング時の処理ではメモリを割り当てません。数値測定は次のコマンドで再現できます。

```sh
cargo run -p auris-synth --example measure_drums
cargo run --release -p auris-synth --example drum_demo -- target/drum-demo.wav
```

リスニングプローブは12個の独立したパッドに続けて8小節のグルーヴを配置し、モーションサンプリングをオンとオフにした場合の重なり合うクラッシュ24件についてコールバックタイミングを報告します。共通ゲインはパッドのバランスを保ちますが、例では各ヒットを個別には正規化しません。

セッションガイドでは、クレートの境界について説明しています。DSPテストはレベルとスペクトルの挙動を確認し、セッションテストはソースの分離、マップの適用、Undo、再生成を検証します。CLI統合テストは実際の子プロセスプロトコルを実行し、受け入れたマップを保存し、再読み込みして再生します。

インストール済みのプラグインスモークテストは`crates/auris-cli/tests/external_drum_probe.rs`に存在します。`AURIS_CLAP_DRUM_SMOKE_PLUGIN`を音の出る初期パッチを持つローカルのCLAP楽器に設定し、次に`cargo test -p auris-cli --test external_drum_probe an_external_clap_snapshot -- --ignored`を実行します。対応するVST3テストは`an_external_vst3_snapshot`で、`AURIS_VST3_SMOKE_PLUGIN`を使用します。これらのチェックは状態の復元、実際の出力、および隔離を確認します。初期パッチにはドラムの割り当ては必要ありません。
