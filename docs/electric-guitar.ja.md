# エレキギターとアンプ

[English](electric-guitar.md)

楽器ライブラリで**Electric Guitar**（`auris.physical.electric_guitar`）を選択し、そのトラックに**Guitar Amp**（`auris.fx.guitar_amp`）を追加します。どちらも内蔵されており、サンプルなしで動作し、通常の楽器/エフェクト状態で保存できます。GMヒント26〜31ではDIを選択してください。アンプは明示的なエフェクトです。作曲家の既存のギター演奏ステージも新しい楽器IDを認識します。

ソングプリセットは現在、各パートの`effects`チェーンにアンプ設定を記述しています。ロックはドライブされたリード/リズムアンプと別々のクリーンパートを備えたブリッジピックアップDIを使用し、ポップ、シティポップ、シンセウェーブもDIギターを増幅します。これらの選択はソング仕様に保存され、作曲後は楽器およびミキサーのコントロールとして編集可能です。

<a id="preset-processing-check-2026-10-05"></a>
## プリセット処理チェック、2026-10-05

ベースラインは`7e1bf88`です。プリセットがネイティブDIを採用した後、アンプを供給する前の状態です。CLIバイナリのレンダリング前後の状態では、宣言された9つのプリセットシードすべてが通常の自動バランス、48 kHzステレオfloat32エクスポート、レンダリングテールなしでレンダリングされました。別個のシード501が4つの影響を受けたプリセットを確認します。8シードのシンボリックレンダーは同一です。保存された13個のスコアすべてがノート、演奏変換、ハーモニー、セクション、テンポを保持しています。すべてのサンプルは有限であり、フルスケール未満です。影響を受けなかった5つのプリセットは、同一のWAVハッシュと学習されたスコアを持っています。

影響を受けたレンダリングごとに、全曲のRMSは0.10 dB未満変化します。2 kHz以上におけるロックのモノフォニックのスペクトルパワー比率は、指定シードで0.0271、シード501では0.0214増加します。これは聴覚判断ではなく、変化した音色の信号測定値です。最初のコーラスの10秒間の抜粋は`target/preset-effects/audition`に保存されており、変更前後共通のRMS目標値は-20 dBFSで、必要に応じて両ピークを0.8未満に保つために低減されます。

固定候補は、ピン留めされたTuneJury/MuQ-MuLan評価器と変更されていないプロンプトを使用して、ゲイン正規化なしで3つの10秒間のウィンドウを使用して測定されました。これらの宣言されたシードデルタは`after - before`です：

| プリセット | TuneJury報酬 | MuQ正コサイン | MuQコントラストマージン |
| --- | ---: | ---: | ---: |
| ポップバンド | -0.005291 | -0.005002 | -0.002724 |
| シティポップ | -0.000226 | -0.000302 | -0.000478 |
| 岩 | -0.527206 | -0.002160 | +0.004092 |
| シンセウェーブ | -0.018346 | +0.001063 | +0.002663 |

ロックの好意度報酬は大幅に低下し、コントラストマージンはわずかに上昇します。ドライブされたアンプは要求されたギタートーンに対応しています。これらの測定結果は、リスナーの好意度が向上したことを示していません。学習スコアの検索やリスナー調査は実施されていません。シード501は学習スコア一般化ではなく、音声の安全性とスコアの不変性を検証します。ウィンドウごとの完全なスコア、チェックポイント/パッケージの由来、ソースおよびオーディオハッシュ、信号測定値、抜粋位置は[`preset-effects-2026-10-05.json`](../tools/eval/references/preset-effects-2026-10-05.json)にあります。

比較を繰り返すには、ベースラインと候補のCLIバイナリを凍結し、各ビルドに対して[symbolic ruler and learned evaluator](evaluation.ja.md)を実行し、後者に`--preset all --seeds 1 --cli <frozen-cli>`を渡します。シード501の場合、各影響を受けたプリセットを`--seed 501`で構成し、その保存済みプロジェクトを`--bit-depth 32 --no-tail`でレンダリングします。既存のプロジェクトは保存済みのエフェクトを保持します。これらの初期チェーンを受け取るには、更新されたプリセットから新しいピースを構成します。

<a id="the-signal-path"></a>
## 信号経路

エレクトリックギターは、アコースティックギターの有限幅ピックアップ、パッシブロス、オールパス調律の弦ループを共有しています。独立したピックアップ観測は、アコースティックボディからの放射を防ぎます。位置依存のコームと運動の微分は誘導電圧を近似し、共鳴低パスはピックアップ/ケーブルのカラーリングを近似します。これは特定のギターの磁石、巻線、または電気回路の再構築ではなく、縮小されたモデルです。

ピックとピックアップの距離は開放弦の長さを指します。標準チューニングE2/A2/D3/G3/B3/E4と最も高い演奏可能な弦がフレットを決定し、有効ストリングの長さを短くします。MIDIにはここではストリング/フレットの識別はありませんので、変則的なフレット配置は表示されません。ピックアップの位置は5 msの間スムーズに変化し、振動ループやピッチを変化させません。ピックアップの共鳴とQはノート中に変化する可能性があります。ピックの接触は次のアタック時に変化します。E4では減衰が基準値です。**Decay per Octave**はE4以上ではそれを掛け、E4以下では割ります。結果は0.1〜40秒に制限されます。校正されたE2〜D6レジスターの外側のピッチは、制限された幾何学と低音域の電圧スケールで演奏可能です。

| DI制御 | 工場出荷時の値 | 意味 |
| --- | ---: | --- |
| 接触硬さ | 0.186606 | 初期のプルック接触の幅 |
| 励振位置 | 0.069559 | 開放弦の長さの分数の形で距離を選択します。 |
| 共鳴減衰 | 7.493398秒 | E4でのダンピング前の公称基音T60 |
| ダンピング | 0.021633 | 追加の基音と高次部分音の追加損失 |
| ピックアップ位置 | 0.235997 | ネック側の位置；0.064146がフィットしたブリッジ設定を提供します |
| ピックアップ共鳴 | 2717.688 Hz | 電気応答の低域周波数 |
| ピックアップQ | 1.883881 | 共鳴の鋭さ |
| オクターブごとの減衰 | 0.55 | 音域依存の減衰比率 |

ギターアンプは、単一の対称なソフトクリッピング段の前にベース/ミドル/トレブルコントロールを備えています。8×オーバーサンプリングと257タップブラックマンウィンドウ化されたsinc補間／デシメーション、そしてオーバーサンプリングされたDCブロッカーを使用します。固定FIR遅延は32ホストフレームで、エンジンに報告されます。ドライブと出力は20ms間でスムーズです。解析的なオープン／クローズドキャビネットはデシメンテーションに従い、バイパスできます；測定されたスピーカーインパルスレスポンスではなく、共鳴EQと2つのローパスセクションを使用します。すべてのチャンネルストレージは`prepare`に割り当てられます。

ドライブはデフォルトで12 dB、トーンコントロールは0 dB、キャビネットはOpen、出力は−6 dBに設定されています。入力レベルは重要です：ドライブを増やすと、ハーモニックコンテンツと圧縮の両方が変化します。デモでは、同じMIDIフレーズで、クリーン/クラッシュ/リード用にDrive 0/18/34 dBを使用しています。

<a id="recording-reference-and-protocol"></a>
## 記録リファレンスとプロトコル

参考文献は[EGFxSet version 1.0](https://zenodo.org/records/7044411)、Hegel Pedroza、Gerardo Meza、Iran R. Romanによるもので、CC BY 4.0ライセンスで提供されています。引用先はPedroza, Meza and Roman, “EGFxSet: Electric guitar tones processed through real effects of distortion, modulation, delay and reverb,” ISMIR Late Breaking Demo, 2022です。[dataset account](https://egfxset.github.io/)は、実際のエフェクトで再生され、クリーンおよび処理済みオーディオの両方の正規化が行われたクリーンなストラトキャスターの録音を説明しています。選択されたペダル録音はBoss BD-2 Blues Driverを使用し、レベル/トーン/ゲイン = 0.5/0.5/1.0です。このペアはペダルの色調を測定しますが、録音されたスピーカーキャビネットのターゲットは提供していません。

MIDI 40〜86の各曲に対して、最も演奏可能な弦の音高を使用して1つの標準的なフレット位置が選択されます。ネックとブリッジピックアップは94のクリーンノートとその94のマッチされたペダルノートを提供します。偶数ピッチはトレーニング（ステージあたり48音）、奇数ピッチは検証（ステージあたり46音）です。両方のピックアップ、クリーン/ウェットペア、そして同じピッチのすべての発生は、同じ分割に残ります。これは、ギター、演奏者、ピックアップタイプ、または速度に関係なく、1つの録音設定内のピッチを維持します。合成ベロシティは0.8に固定されています。なぜなら、録音には校正されたMIDI速度マッピングが提供されていないからです。

フェッチャーは制限されたZIPバイト範囲を読み取り、選択された各メンバーのCRCを検証し、元の/準備済み音声のSHA-256ハッシュを凍結します。公開された完全アーカイブのMD5値はメタデータのみであり、完全なアーカイブはダウンロードまたは検証されません。`target/`ではオーディオは無視されます。事前準備済みのfloat WAVは、libsndfileのタイムスタンプ付きPEAKチャンクを使用せず、決定論的なヘッダーを使用します。開発中、188個のデコード済み波形は、そのヘッダー変換においてビット単位で同一であることを確認しました。以前の診断レポートは、移行前のマニフェストハッシュを保持しています。各録音はモノラル48 kHzです。オンセットはピークの2%に到達する最初のサンプルで、1 msのプリロールがあります。必要に応じて3秒は保持され、ゼロ補填されます；事前準備はポリフェーズフィルターで24 kHzにダウンサンプリングされます。両方の信号は、同じ因果関係のある30 Hzハイパスフィルターと、全ノートRMS正規化0.1を受け取ります。フレーム正規化やタイムワープはありません。

主要な測定方法は、位相重み付きlog-mel L1です：Hann窓512/2048、240サンプルホップ、30 Hz〜10 kHzの64個の面積正規化したHTKバンド、および`log1p(10000 × mel power)`。アタック0〜50 ms、ボディ50〜250 ms、テール250 ms〜3 sの適用ウェイトは0.3/0.3/0.4です。二次的な測定方法は、dBでの20 ms RMSエンベロープL1と、秒単位の絶対90%エネルギー時間誤差です。後者は保持された3秒間のウィンドウを指します。

DIフィッティングは実際の24 kHz Rust PCM、9つの境界制約制御、シード付き差分進化、個体数倍率4、8回のイテレーション、およびポリッシュなし（324回の評価）を使用します。以前の8制御トレーニングフィッティングは検索を初期化します。最終目的関数はL1に`0.006 × envelope dB error + 0.15 × T90 seconds error`を追加します。トレーニング診断の結果、以前の定常減衰候補は高音を長く維持していたことが示され、オクターブごとの減衰制御の導入が動機付けられました。最終検索は提供された初期点を保持しました。これはグローバル最適点の証明ではなく、境界調整です。パラメータの境界値、シード、トレーニングIDはフィッティングJSONに保持されます。丸められたフィッティング制御は工場出荷時のデフォルト値になります。

最初のアンプ比較では2段階の候補が使用され、歴史的な診断として保持されています。改良されたアンプは1つの`tanh`ステージを使用し、既存の1段階ディストーションベースラインと同じ0〜48 dBのドライブレンジを使用しています。ドライブは48のトレーニングノートすべてにのみ適用されます；最終比較では、すべての48のトレーニングノートと46の保持された検証ノートをネイティブの48 kHzワーカーを通じて8ノート単位に処理し、その後24 kHzに再サンプリングします。両方の候補は、キャビネットバイパス付きの同じRMS正規化された録音されたクリーンなDIを受け取ります。完全なレポートとフィットは`tools/eval/references/amp-refinement.json`と`amp-refinement-fit.json`です；チャンク化された評価器は`tools/eval/amp_refinement.py`です。

<a id="measured-results"></a>
## 測定結果

エラーが低い方が良いです。検証には23本の保持されたピッチと両方のピックアップが含まれています。

| 比較 | 変更前 | その後 | 変化 |
| --- | ---: | ---: | ---: |
| DI log-mel L1 | 0.284290 | 0.123607 | 56.52%低い |
| DIエンベロープL1 | 4.8095 dB | 2.2680 dB | 52.84%低い |
| DI T90絶対誤差 | 0.2901秒 | 0.1875秒 | 平均で35.35%低い |
| ブルースドライバー log-mel L1、検証 | 0.067339 | 0.066224 | 1.66%低い |

DIベースラインは、変更前の、すでにアコースティック校正済みのPickup blend=1のギターであり、新たに新たにフィットしたエレクトリックモデルではありません。ペダルベースラインは、別々に最適化された既存のディストーションで、同じDriveの境界とトレーニングのみのフィットを備えています。DIトレーニングmelは0.282219から0.128512に低下します。オクターブ減衰なしの以前の候補は、検証melを49.70%低下させましたが、エンベロープとT90を悪化させました；これらの診断的アーティファクトは依然として利用可能です。

ペアリングブートストラップは、両方のピックアップを一緒に保持したまま、ピッチの2,000回の再サンプリングを使用します。検証用DI平均mel差分は記述的な95%区間[−0.184786, −0.131593]、エンベロープ差分[−3.0386, −1.9211]dBを持っています。T90デルタの区間[−0.2082, +0.0128]sは0を越えているため、その低い平均値は同様に明確な改善を示していません。ペダルのmel差分区間[+0.008795, +0.016097]は、歴史的な2段階候補に属します。改良されたアンプの検証用mel差分は0.067339から0.066224に低下し、ペアリングデルタ区間[−0.001333, −0.000912]となります。そのトレーニング用mel差分は0.0707509から0.0693664に低下します。キャビネットの周波数応答およびアンチエイリアステストは、録音されたアンプ/キャビネットへの忠実度ではなく、DSPの動作を確立します。これらの区間は、モデル開発後の記述的な値であり、未改変の最終テストや知覚品質スコアではありません。

各ノートのエラー、工場出荷時/フィット済みパラメータ、参照/レンダラーハッシュ、およびメトリック設定は`tools/eval/references/electric-validation.json`にあります。固定コホートとフィットアセットも同じ場所にあります。数値Rustテストはチューニング、独立したピックアップの音色、極端なコントロール/レート、測定されたFIR遅延、エイリアス抑制、キャビネット応答、割り当て不要のコールバック/コントロール変更、リセット、ブロックサイズ独立性をカバーしています。セッションテストは構成、保存済みの楽器/エフェクトコントロール、再オープン時のレンダリングPCMが同一であることを確認します。開発機では、48 kHzステレオ、256フレームの24声のエレクトリック/アンプコールバックが、512ブロックあたり5.333 msの予算で平均0.365 ms、p99 0.523 msを使用しています。これはローカルのタイミング測定であり、すべてのCPUに対する保証ではありません。シンボリックルーラーの行および9つのプリセットWAVハッシュ/Audioboxスコアは変更されていません。これらのプリセットは新しいプラグインを使用していないため、これは回帰動作のみを確立しています。`tools/eval/references/electric-regressions.json`はペアリングされたプローブ、タイミング、および同一RMSの試聴の由来を保持しています。

<a id="reproducing-and-auditioning"></a>
## 再現とオーディション

元のDI測定では、`ba18d5e`および`f022ceb`のワーカーが使用されていました。現在のアンプ比較では、`f022ceb`のワーカー`physical_fit_render`を別々のチェックアウトで`<before-worker>`として保持してください。Windowsでは`.exe`のサフィックスを使用してください。現在の全コホートのアンプ比較を再現するには：

```sh
cargo build --release -p auris-synth --example physical_fit_render
uv run tools/eval/fetch_electric_reference.py target/electric-guitar/reference
uv run tools/eval/amp_refinement.py --renderer <new-worker> --baseline <before-worker> --fit tools/eval/references/amp-refinement-fit.json --out target/physical-next/amp-validation.json
```

保存されたコントロールを再生する代わりに、現在のアンプのトレーニング検索を繰り返すには、次の手順を実行します。

```sh
uv run tools/eval/amp_refinement.py --renderer <new-worker> --baseline <before-worker> --out target/physical-next/amp-validation.json
```

3つの編集可能なサンプルなしのプロジェクトとそれらのネイティブのWAVエクスポートを作成します。

```sh
cargo run --release -p auris-session --example electric_demo -- target/electric-guitar/demo
cargo run --release -p auris-synth --example physical_bench -- --amp
```

この例では、フォルダーごとに1つのプロジェクトを保存し、プロジェクトのアセットルールを保持します。3つのドライブ設定を比較する際は、フレーズ全体のレベルを合わせて試聴します。フレームごとの正規化やリミッターは必要ありません。ネイティブエクスポートでは、実際のプラグインレベルが保持されます。
