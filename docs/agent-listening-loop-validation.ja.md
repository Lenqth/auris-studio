# ライブレンダリングされたオーディオフィードバックの検証

[English](agent-listening-loop-validation.md)

2026年10月21日、アプリ内のCodexバックエンドは、現在の未保存ドキュメントを使用して実際の作曲、オーディオレビュー、ローカル編集、A/Bレビューを完了しました。Claude CodeはネイティブのCLIと限定的なライブMCP接続に到達しましたが、SonnetとHaikuの両方ともツール呼び出しを行う前にアカウントセッション制限に達しました。実際のリスニングループはまだ検証されていません。

<a id="implementation-and-scope"></a>
## 実施と範囲

共有ライブ`listen`コマンドは、開いたドキュメントをスナップショットし、48 kHzで1〜8バー（最大30秒）をレンダリングし、実際のPCM16 WAVバイトを構成された音声批評モデルに送信します。コントローラーの直接オーディオ入力サポートとは独立して動作します。CodexとClaude Codeは、批評モデルのテキストと正確なWAV測定値を受信しますが、コントローラー自体はWAVを受信したり再生したりしません。

レンダリング、エンコーディング、推論はバックグラウンドワーカー上で実行されます。既存の`edit_project.listen`権限は、スナップショットを取得する前にネットワーク承認/審査が必要です。変更されたドキュメント、拒否されたルール、キャンセルされた会話は保留中の結果を拒否します。キャンセルは後段階を阻止しますが、実行中のHTTPリクエストは制限されたタイムアウトまで実行できます。リスナーコールはプロジェクトを保存したり、フェーダーを変更したり、Undoチェックポイントを作成したりしません。

セッションには、不透明なIDで識別される4つの変更不可能な生の抜粋が保持されます。A/Bリクエストには、同じバー、テンポマップ、メーターマップを使用する必要があります。その前後のファイルは、相対的なレベル変化をマスキングすることなく両方を保護するために選択された1つの減衰値を使用します。推定値は4倍FIR分析を使用して-1 dBの真のピークをターゲットとしています。これは認定されたBS.1770測定ではありません。エンコードされたファイルはアップロード前にデコードして確認されます。ソース過負荷、適用された減衰値、エンコードされたピーク/RMS、および正確なWAVハッシュは別々に報告されます。オーディオ保護は過負荷状態のプロジェクトを修正するものではありません。

保存されたプロジェクトのMCPプレビューも保護されたライターを使用します。そのファイルパス比較ワークフローは、ライブの不可変IDとは依然として異なります。この作品では、コンポーザーライターや楽器のサウンド定数は変更されていません。

<a id="actual-backend-trials"></a>
## 実際のバックエンドトライアル

オプトインGPUIハーネスは、ディスプレイ、アプリケーションGPU、オーディオデバイスなしで、実際のアプリケーションワーカー、ネイティブCLI、ライブMCP、AutoReview、セッション、レンダラーを実行しました。Ollamaは既存のローカル`gemma4:e2b`音声対応批評モデルを提供しました。これらはツール駆動型の音声送信トライアルであり、スピーカー再生や人間の聴き取りではありません。ハーネスは空の初期プロジェクトを保存し、エージェントにライブセッションの編集を許可し、エージェントが終了してからのみ最終ドキュメントを保存しました。ホストの保存はエージェントの動作ではありません。直接のセッションテストは、さらにプロジェクトパスなしでの聴き取りもカバーしています。

各バックエンドは同じリクエストを受け取りました：メロディー、伴奏、名前付きセクションを備えた明るい16バーのポップソングを作成する；レンダリングされたオーディオをローカルの批評家に提出する；サポートされている問題を修正する；同じセクションを比較する；不確実性を報告する。

| --- | --- | --- |
| Codex CLI 0.163.0、`gpt-6.1-sol`、高い努力 | 178.30秒で通過しました | 4トラック、470ノート、Cメジャー、124 BPM；イントロ、ヴァース、プレコーラス、コーラス、アウトロ；2つの成功したオーディオレビュー、中間には編集/リードバックがあります。 |
| クロードコード2.1.304、`sonnet`、高い努力 | 15.04秒でブロックされました | CLI/MCPの起動に成功しました；ツール呼び出し前のセッション制限 |

Claudeは報告しました：`You've hit your session limit · resets 5:40pm (Asia/Tokyo)`。報告されたリセットは**2026-10-21 17:40 JST**です。共有ツールテストと成功したMCP接続は、完了したClaudeコンポジションやリスニングトライアルではなく、統合範囲の確立を示しています。承認もクオータも回避されていません。

<a id="codexs-completed-feedback-loop"></a>
### Codexの完了したフィードバックループ

Codexは、修正528における7.742秒のコーラスバー9〜12をレビューした。批評家は、やや埋もれがちなものの比較的明確なメロディーと、バランスやフレーズの確実性については不確実であると述べた。Codexはノートの書き換えではなく、小さなアンサンブル変更を選択した。具体的には、ピアノの音量を1.5dB下げ、ピーク天井でミックスを正規化し、ミキサーを再生してレンジを確認した。

その後、534番目のバージョンで、前の不変なバージョンと同じバーの現在のレンダリングを送信しました。正規化により全体的なゲインが移動しましたが、意図された相対的なピアノの減衰は維持されました。両方の比較抜粋は保護減衰をゼロにしました。前のWAVハッシュは元のベースラインと完全に一致しましたが、現在のWAVは異なります。

| エンコードされた抜粋 | サンプルピーク | RMS | 保護的な減衰 |
| --- | ---: | ---: | ---: |
| 初期コーラス/以前に保持された | -1.696 dBFS | -19.403 dBFS | 0 dB |
| 改訂されたコーラス | -1.793 dBFS | -19.632 dBFS | 0 dB |

ソース抜粋にはフルスケールのサンプルが含まれていませんでした。実際のエンコードファイルもピークガードに合格しました。保存された最終プロジェクトはSHA-256 `6f8c00f413ada38c6ef99df2e36da7768aceada571fbb021bef469513e7611c6`を持っています。

2番目の批評家の回答は、メロディーが聞き取りやすくなったか、伴奏が弱すぎるかを確信を持って区別することができませんでした。また、提供された編集説明を繰り返し、編集ツールが一切使用されていないにもかかわらず、ピアノの音量を下げるといった第一人称の表現を使用しました。これは聴覚的判断の信頼性の欠如と、プロンプトの影響の可能性を示す証拠であり、聴覚的判断の証明ではありません。Codexの最終回答は、不確実性を正しく報告していました。この実験はループが実行されることを証明していますが、音楽的品質の向上や信頼できる批評家が存在することを証明するものではありません。

機械可読プロンプト、ツールシーケンス、実際のレビュー、修正/範囲データ、WAV測定値/ハッシュ、CLIバージョン、ソースハッシュは[`cli-agent-listening-2026-10-21.json`](../tools/eval/references/cli-agent-listening-2026-10-21.json)に保存されます。生のトランスクリプトとコピーされた最終プロジェクトは、無視されたローカル評価ディレクトリに残ります。一時的な批評用WAVは、各リクエスト後に削除されます。

<a id="reproduction"></a>
## 複製

`AURIS_AUDIO_URL` と `AURIS_AUDIO_MODEL` を通じて利用可能な音声対応批評モデルを構成し、コントローラー CLI をインストール/認証します。絶対的な `workspace`、`output`、UTF-8 `prompt` ファイルパス、`backend: "codex"` または `"claude"`、サポートされている `model`、`effort`、`timeout_seconds: 1200`、`natural_workflow: true`、`listening_required: true` を含む JSON コンフィギュレーションを作成します。出力ディレクトリは新しいものである必要があります。`AURIS_CODEX_TRANSCRIPTION_EVAL` をその構成に設定し、実行します：

```powershell
cargo test -p auris-gpui --bins -- --ignored --exact ui::agent_chat::transcription_eval::installed_cli_composes_and_relistens_in_the_window --nocapture --test-threads=1
```

このテストには実際の音声の送信、変更不可能なベースラインの照合、文書の改訂の増加、レビュー間の状態の読み戻し、共通のA/B減衰が必要です。レビューの失敗やネイティブのバックエンドの制限は依然として失敗として扱われます。このテストでは、実際の批評家への処理をスクリプト化した応答で代用しません。

<a id="regression-coverage"></a>
## レジリエンスのカバー率

セッションテストは、保存されていないレンダリング、スクリプト化されたHTTPフィクスチャへの実際のWAVアップロード、変更されていないベースラインバイト、過負荷時の相対ゲインの保持、ソース/エンコード測定、ドキュメント/バージョン所有権、タイミング変更、保持の削除、キャンセル、非有限サンプル拒否をカバーします。保存済みプレビューのレグレッションでは、高ゲインでのPCMクリッピングを最初に再現し、現在では保存済みプロジェクトを変更せずに保護をチェックしています。ホスト/ポリシーテストは権限の順序をカバーし、デスクトップテストはワーカーのキャンセル、変更されたドキュメント、拒否されたルールをカバーします。

PCの再起動により以前のビルドが中断されましたが、ソース変更は残りました。1つのCargoビルドジョブでテストが再開されました。Windowsテストフィクスチャのクリーンアップ競争は、会話ストレージのフラッシュ待ちにより修正されました。広範なワークスペース実行はすべてのセッションおよびデスクトップテストに合格しましたが、`listen`を追加した後、古いツールボックスカタログ件数期待値が見つかりました。その期待値は修正され、影響を受けたパッケージテストと残りのパッケージテストは再実行で合格しました。フォーマットおよびワークスペースドキュメントテストは合格しました。厳格なワークスペースClippyは、検証証拠とともに別々に記録されています。
