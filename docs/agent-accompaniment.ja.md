# 作者によるメロディのためのアルゴリズム的伴奏

[English](agent-accompaniment.md)

ライブエージェントと保存済みプロジェクトのMCPツールは`accompaniment`を公開します。エージェントは`edit_notes`で前景メロディを編集し、次にAurisにベース、コード、パッド、アルペジオ、または割り当てられたドラムを書き込ませることができます。リクエストには役割、範囲、レシピ制御が含まれ、レスポンスには完全なノート配列ではなく、クリップID、ノート数、レシピ概要が含まれます。

まずプロジェクトを確認してください。音楽的な役割に基づいて前景を特定し、そのクリップIDを`foreground_clips`と`protected_clips`の両方にコピーしてください。前景は保護されたクリップの空でない部分集合である必要があります。これは、手書きやレシピのないインポートされたノートを含む、コード/アルペジオの間隔のための手書きメロディノートを明示的に選択します。追加の保護されたクリップはこの音楽的前景に参加する必要はありません。保護は、作成されたノート、曲線、歌詞、演奏、レシピを含むすべてのクリップを保持します。メロディから新しい進行を推論することはありません。`suggest_harmony`と`edit_harmony`で意図的に和音を選択してください。既存のフレーズ作成と伴奏調整アルゴリズムがスコアを生成します。7度、サスペンション、またはディミニッシュコードは、チャートの必須の割合ではなく、音楽的な選択です。

明示的な前景処理は、選択されたノートウィンドウとループの繰り返しを組み合わせ、ミュートされたトラック/クリップやゼロベロシティのノートをスキップします。これはターゲットあたり4096個の保存済みおよび拡張されたノートに制限されます。パフォーマンス変換、ベンド、ソロルーティングはシミュレーションされません。返送された各クリップには、ソースノート数、バックグラウンドの前後数、スコアの変更有無、および適応をスキップした理由を含む`adaptation` レポートが含まれています。明示的なリズム、駆動するコードの密度、持続的なアンビエントテクスチャ、ベース/パッド/ドラムの役割はパターンを保持します。スコアの変更やノート数の減少は、好みの主張を暗示するものではありません。

<a id="propose-harmony-from-the-motif"></a>
## モチーフから調和を提案する

進行を変更する前に、読み取り専用の`suggest_harmony`ツールを呼び出してください。

```json
{
  "request": {
    "melody_clips": [10],
    "start_bar": 1,
    "bars": 4,
    "mood": "dreamy",
    "ending": "settled"
  }
}
```

プロジェクトキーは、`request.key`が明示的に別のキーを指定しない限り使用されます。ムード名は `neutral`, `bright`, `dark`, `calm`, `driving`, `epic`, `dreamy`, `tense`, `funky` です。`ending` は `settled`（互換性がある場合はトニックな着陸を好みます）または `open`（継続を許可します）です。ムードはサポートされている色とハーモニック変更のコストを調整しますが、キーは決して変更しません。

結果には、ヒューリスティックな適合度順に並べられた最大3つの異なる候補が含まれ、常に最も強いシンプルなメジャー/マイナー三和音の代替案が含まれます。長音とアクセント音は、短い通過音よりも重み付けされます。セブンスはメロディックなサポートを必要とし、サスペンションは4度の後に3度で解決する必要があります。ディミニッシュハーモニーはメロディックなサポートと、音高クラス間の移動が小さい後続コードを必要とします。繰り返されるモチーフは関連するハーモニーを促します。緊張した雰囲気でも、追加されたトーンや小節内の変更には必ずコストがかかります。色彩がシンプルな代替案よりも意味のある改善をもたらさない場合、結果にはその代替案のみが含まれます。複雑さの目標はありません。

各候補者は、コード名、バーごとの理由、重み付けされたメロディックフィット、およびコード外の目立つノートを報告します。これらは聴覚結果や芸術的評価ではなく、象徴的なヒューリスティックです。分析はループを含むクリップウィンドウ内の作成されたノートを読み取りますが、パフォーマンスの変換、ベンド、トーンカラー、オーディオはその証拠の範囲外です。文脈の中で未解決の緊張を聴覚的に判断してください。

レスポンスの`revision`、`protected_clips`、`foreground_clips`、および選択された候補の`harmony`オブジェクトは、`operation.kind = "regenerate"`と明示的な伴奏クリップIDを付与したまま、`accompaniment`に直接渡されます。これによりハーモニーが適用され、1回の Undo 操作で該当するクリップのみが書き換えられます。プロジェクトが承認前に変更された場合は、新しい提案をリクエストしてください。新しい伴奏を作成する場合は、選択したチャートに`edit_harmony`で適用し、更新された`revision`を確認してから生成してください。提案自体は、保存済みプロジェクトのMCP呼び出しを含む場合でも、ドキュメントや履歴を変更しません。

リクエストは1〜16小節、最大128拍で構成され、1〜8つの異なる音高のメロディクリップと、最大4096の保存/展開済みノートを含みます。キーまたは拍子の変更時に分割されます。サポートされるキーは、メジャー、ナチュラル/ハーモニック/メロディックマイナー、ドリアン、リディアン、ミクソロディアン、フィリジアンです。メロディノートのないフレーズは拒否され、フレーズ内の休止は前の和音を保持します。

<a id="generate-and-regenerate-backing"></a>
## 伴奏を生成および再生成する

別々の伴奏トラックを作成し、通常のトラックツールを使用してそのサウンドを選択します。ドラムの場合、生成する前にトラックのサウンドを割り当てます。`inspect_project`からトラックIDと現在のコンテンツ `revision` をリクエストにコピーします。以下の例のIDはプレースホルダーです。保存された呼び出しは、同じ引数に `project` パスまたはプロジェクトID を追加します。

```json
{
  "expected_revision": "revision-from-inspect_project",
  "protected_clips": [10],
  "foreground_clips": [10],
  "operation": {
    "kind": "generate",
    "parts": [
      {
        "track": 2,
        "name": "Verse bass",
        "part": "bass",
        "start_bar": 1,
        "bars": 4,
        "seed": 23,
        "settings": { "density": 0.65 }
      },
      {
        "track": 3,
        "name": "Verse pad",
        "part": "pad",
        "start_bar": 1,
        "bars": 4,
        "seed": 42
      }
    ]
  }
}
```

返送されたクリップIDを保持します。進行を変更し、選択したバックグラウンドのみを書き換えるには、現在のバージョンを読み取り、ハーモニーの置き換えとともにこれらのIDを渡します：

```json
{
  "expected_revision": "current-revision",
  "protected_clips": [10],
  "foreground_clips": [10],
  "operation": {
    "kind": "regenerate",
    "clips": [11],
    "harmony": {
      "start_bar": 1,
      "bars": 4,
      "key": "C major",
      "chords": "| Imaj7 | IVsus4 | viidim7 | V7 |"
    }
  }
}
```

ここではクリップ11は新しいハーモニーを反映しており、クリップ12と前景は保存されたノートを保持しています。ハーモニーはすべてのトラックが共有するプロジェクトメタデータです。したがって、選択されていないバックグラウンドはまだ前の進行を反映している可能性があります。意図するターゲットを明示的に選択してください。別の `edit_harmony` もノートを保持します。現在のプロジェクトハーモニーを使用するには、後の `regenerate` リクエストから `harmony` を省略してください。レシピコントロールの変更も依然として明示的な `edit_recipe` 操作です。

再生成はクリップID、位置、長さ、ループ設定、レシピ制御およびシード、作成された曲線、パフォーマンススタックを保持します。手動で編集された生成スコアは書き換えではなく拒否され、凍結されたクリップには再生成するためのレシピがありません。保護された前景は手動で作成するか生成できますが、どちらもこのツールによって書き換えられません。

各操作はワーカー上で所有するスナップショットを作成し、その生成元ドキュメントが変更されておらず、リクエストがキャンセルされていない場合にのみ公開します。生成失敗は、ライブドキュメントもUndo/Redo履歴も変更しません。Harmonyおよび選択された伴奏はすべて1つのUndoステップを構成し、保存された実行チェックポイントは変更を記録します。古いバージョンで完了した生成を再試行すると拒否され、使用中のターゲット範囲も拒否されます。

制限：保護されたクリップは1〜16個、パートまたは異なる再生ターゲットは1〜16個；ターゲットあたり最大64バー、最大256クォーターノート、1回の操作あたり最大1024クォーターノートおよび65,536個の生成ノート。リクエストは空でないクリップを生成する必要があります。内部のメトロ/セクション変更時にターゲットを分割し、リクエストされたハーモニーの置き換えを超えて広がっているクリップも分割してください。スナップショットはシリアル化されたプロジェクトデータで最大64 MiBに制限されます。レシピ設定は既存の`edit_recipe`語彙を使用してください。各生成パートの`seed`を使用し、`settings.seed`は省略してください。

返送された要約を確認し、同じレンダリングされたバーを`inspect_audio`またはプレビューと比較してください。保持されたノートと正しい再生は構造上の保証であり、音楽の品質の評価ではありません。保存されたレシピは通常の契約を維持します：シードはビルド内で再現可能であり、フリーズは作曲家の変更にもかかわらずテイクを保持します。
