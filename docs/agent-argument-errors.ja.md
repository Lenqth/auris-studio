# エージェント引数エラー：原因と検証

[English](agent-argument-errors.md)

日付：2026-10-22。
実装：`f233bdc5`。

先行する作曲の再実行では、4つのシナリオをすべて完了したものの、4件の引数拒否から復旧した。このフォローアップでは、作曲アルゴリズムやツール数を変更せずに、その拒否に対処する。

## 原因と変更

2回の `read_notes` 呼び出しで、実際のクリップアドレス `5,6,7,8` ではなく、トラックアドレス `1,2,3,4` をコピーしていた。作成結果ではすでに `track` と `clip` を区別していたが、`inspect_project` は両方の入れ子の値を `id` と表示していた。共有指示とツールの説明にも、由来を示さずにクリップ番号 `1,2` を例として載せていた。正しい入れ子の値を含む検査の直後でも失敗した呼び出しが1件あり、情報が利用できるだけでは誤りを防げなかった。

モデル向けのプロジェクト検査では、作成結果とツール引数に合わせて、数値アドレスを `track` と `clip` と明記するようにした。作曲用の検査も同じ語彙を使う。主要な指示では、ノート操作の値の出所を `tracks[].clips[].clip` と示し、前置きから固定番号の例を削除した。無効なノート読み取りアドレスには、誤ったトラック ID を示し、最大8組の有効なトラック／クリップの組を返す。トラックからクリップを推測したり、ドキュメントを変更したりすることはない。永続化されたプロジェクト ID とファイル形式は変更していない。

もう一方の呼び出しでは、`edit_recipe` に細分 `quarter` とリズム `h h` を渡していた。送信されるスキーマでは、どちらのフィールドも制約のない文字列だった。制限はフィールドの説明にしかなく、コンパクト化されたスキーマでは意図的に削除される。そのため、コントローラーには機械可読な選択肢一覧もリズムのアルファベットもなかった。これらはグリッドの制御値であり、細分はステップ間隔を選び、リズムはヒット／休符のパターンを表す。任意の保持音長名は受け付けない。

レシピの細分は、既存のコア列挙型にデシリアライズするようになり、4つの正規名をコンパクトな JSON Schema に残した。リズムは、実際のパーサーが使うアルファベットと長さの上限をそのスキーマに公開する。主要なツール説明では、ステップ構文を説明し、ノート数と保持長には density と gate を使うよう示す。この案内は説明を圧縮しても残る。実行時エラーではリズム記法を説明し、有効な例を示す。追加のツールやフォールバック用の別名は導入していない。

回帰テストでは、ワイヤー制約の欠落、正規列挙値の往復、正しいステップパターン、パターンのクリア、部分編集を伴わない無効なリズムの拒否、検査したアドレスの曖昧さがないこと、ドキュメントを変更しない実用的な誤トラックエラーを対象にした。細分の列挙が元のスキーマに存在しなかったため、ワイヤー制約の回帰テストは元のスキーマでは失敗した。

13ターンはすべて、先行実行の4件に対して、引数／ツールエラー0件で完了した。総呼び出し数は305 → 265、ノート読み取りは35 → 24だった。生成された音楽は実行ごとに異なるため、これらの数値は記述的なものであり、速度や信頼性のベンチマークではない。再生成のフォローアップでは、対応していない音長名を使わず、density、gate、seedを直接使った。初回の作曲では `eighth` と `x.x.x.x.` のレシピ制御も正常に使った。アレンジメントの最初のノートバッチでは、トラック `1,3,5,7` とは異なる、実際にインターリーブされたクリップアドレス `2,4,6,8` を使った。

4つの WAV はすべて48 kHz／24ビットで、要求した長さからの差は1サンプル以内だった。すべての MIDI ファイルを再インポートでき、ノートが存在した。書き出しのターンでは、各ドキュメントは変更されず、未保存のままだった。ギターの単音アルペジオには対象となるコードグループがなく、保存されたストラムの広がりはストロークを生成しないと Codex は正しく報告した。Undoのターンでは、プロジェクト検査、履歴読み取り、保護された履歴の取り消し、プロジェクト検査を行い、ノート配列を再構成しなかった。

### 残ったオーディオ配信の失敗

16小節のアレンジメント WAV は0 dBTPに達し、フルスケールのサンプルを2つ含んでいた。`verify_render` は `verdict:FAIL`、`peak_ok:false` を返した。Codex はクリッピング検査の失敗と再レンダリングの必要性を明示し、正常な配信だとは主張しなかった。ファイルは34.285708秒で、MIDIノートは587個だった。スコアとUndoの検査は通過したが、このオーディオ配信基準は失敗した。他の3つの WAV は無音ではなく、フルスケールのサンプルもなかった。この結果は、別のランダムな作曲を通過するまで再実行せずに保持した。

これは、4つの引数の誤りが再発したものではなく、別に観測されたミキシング／書き出し結果である。この引数契約の変更では未解決のままだった。この試行から、音楽的品質やモデルの普遍的な信頼性についての主張は導けない。

保持したプロジェクトで WAV のクリッピングを再現し、出力ヘッドルームのフォローアップで修正した。その別の同一プロンプトによる Codex の再実行では、エンコード済み WAV の4つの配信検査すべてに合格した。
