# 実験的な作曲ワークフロー

[English](composition-workflows.md)

Auris の起動前に `AURIS_COMPOSITION_WORKFLOWS=1` を設定すると、共通プロンプトを短縮し、タスク別ワークフローを試せます。ツールカタログ全体は変わらないため、プロンプト実験でツールの異なる条件を暗黙に比較することはありません。既定では、聴取の証拠が変更を支持するまで既存のプロンプトを使います。候補ツールを案内するには `AURIS_COMPOSITION_CANDIDATES=1` も個別に設定し、両条件で同じ値にしてください。評価ランナーは両条件でこのフラグを有効にします。既定のアプリケーションカタログを試すときは `--no-candidate-tools` を使います。ローカルモデルのコンテキストは既定で64kで、`--context-tokens` で明示的に記録できます。実験で予算を増やしても、アプリケーションの既定値は変わりません。

両プロファイルは、ボーカル曲全体の形式に関する案内を共有します。新しい曲で指定がなければ第2ヴァースと後半のコーラス／エンディングを含め、短い形式を明示した場合や局所編集ではその範囲を保ちます。したがって既定プロファイルでもこの動作になります。セクションの網羅とスコアの読み戻しについては、[ライブボーカル制作](agent-workflows.ja.md#live-vocal-production)を参照してください。

`production_record` は `select_workflow` を受け取り、`workflow`（`composition`、`accompaniment`、`vocals`、`local_edit`、`delivery`）と `writing_order`（`harmony_first`、`melody_first`、`rhythm_first`）を指定します。選択は会話メタデータであり、他の記録更新と同じ書き込み権限の対象です。コンテキスト圧縮や会話の再起動後も保持されます。モジュールモードでは、応答と後続のプロジェクト検査に、選択したタスクの指示だけが含まれます。タスクが変わった場合、エージェントは選択を明示的に変更できます。

共通契約は、正確なID、ティック単位、リビジョン検査、ソース保持、探索上限、測定値・批評家レポート・人間の聴取の区別を維持します。ワークフロー指示はモデル向けの案内であり、正規のセッションコマンドが検証と権限を個別に強制します。保留中の候補判断は、その有効期間内ならターンをまたいでラウンドとIDを保持します。ターンの終了だけを理由にラウンドをキャンセルしないでください。

制御された比較では、同じ固定実行ファイル、モデル、タスク群、ツールカタログを使い、`composition_quality.py run --prompt-profile legacy` と `--prompt-profile modular` を実行します。バックエンドのトークンカウンターとともに失敗と経過時間を記録してください。最後に報告された入力コンテキストは累積課金入力ではないため、利用量が欠落している場合にゼロコストとして扱ってはいけません。モジュールプロファイルを既定に採用する前に、盲検した人間の好みとリクエスト遵守を確認してください。
