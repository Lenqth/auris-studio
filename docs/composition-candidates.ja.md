# 正確な作曲候補

[English](composition-candidates.md)

ライブエージェントパネルで実験的な候補ツールとフレーズツールを案内するには、Auris の起動前に `AURIS_COMPOSITION_CANDIDATES=1` を設定します。追加スキーマには余分なコンテキストが必要です。候補ラウンドの途中で履歴が64kのローカルモデル予算を使い切ることがあるため、対応する予算を選び、予算超過の失敗も評価結果に残してください。通常の32kカタログは既定で利用できます。保存済みプロジェクトのMCPは、手動／作曲ツールグループを通じてこれらのコマンドを公開します。

`candidates` はライブエージェントと保存済みプロジェクトMCPで共有されます。変更不可能なベースラインと1〜3個の候補を作成します。ノート候補は `edit_notes` と同じ検証を使い、伴奏候補は保護クリップIDと前景クリップIDを明示します。楽器とドラムのノート編集に対応します。

1. ドキュメントを検査して対象ノートを読み取り、音楽的な目的と固定する内容を示します。
2. その内容のリビジョンと独立した候補を使ってラウンドを作成します。各候補はベースラインから開始し、別の候補からは開始しません。
3. 変更されたクリップの要約と、ページングされた正確な変更前後のノートを読み取ります。新しい伴奏クリップIDは候補スナップショットに属します。
4. すべての候補で同じ短い範囲をプレビューします。WAVは1つの保護ゲインを使い、エンコード後の測定値を報告します。個別に正規化したり採点したりはしません。音楽的な好みの判断には聴取が必要です。
5. 元のリビジョンで選択した候補を適用するか、キャンセルします。適用は評価済みスナップショットをコピーし、ライターを再実行しません。ライブアプリケーションではUndo編集を1回行います。同一リクエストの再試行で別の編集は作られません。

ラウンドは15分後に期限切れとなり、元のドキュメントに属します。ライブドキュメントの変更、キャンセル、古いワーカーの結果は採用を阻止します。保存済みツールは、内容が変わらない間は同じ正規プロジェクトパスを再び開けます。探索は、リビジョンごとに最大3ラウンド、ラウンドごとに最大3つのプレビュー範囲に制限されます。プロセスは最大8ラウンドと、スコアスナップショット256 MiB（1ラウンド64 MiB）を保持します。プレビューのパスはラウンドがキャッシュされている間だけ有効で、キャンセルすると削除されます。ツールが勝者を自動選択することはありません。

<a id="scoped-phrase-variation"></a>
## 範囲を限定したフレーズ変化

`phrase_variation` は1つの楽器またはドラムクリップを読み取り、パッチと正確なノート差分を返します。`request` には `clip`、クリップ相対の `start_tick` と `end_tick`、`protected_indices`、`operation` が含まれます。

- `pitches`: `preserve_prefix_until_tick` が冒頭を保護し、`changes` に `{index, pitch}` を指定します。リズム、長さ、ベロシティ、その他のノートフィールドは固定されます。
- `cadence`: `landings` に `{index, pitch, length_ticks}` を指定します。アタック、ベロシティ、指定されていないフィールドは固定されます。元のノートと提案ノートは、要求範囲内に完全に収まる必要があります。

各操作は1〜128個の重複しない変更を受け付けます。保護済み、重複、欠落、範囲外のノートはドキュメント編集前に失敗します。応答には同等の `edit_notes` パッチが含まれます。保護検査を保ちながら不変候補を比較・採用するには、元のリクエストを `candidates` の編集 `{kind:variation, request:...}` として送信します。値は明示的に作成されたもので、音高変更がフレーズを改善すると操作が推測することはありません。
