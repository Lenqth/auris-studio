<a id="resulting-contracts"></a>
## 結果として得られた契約

保存済みプロジェクトMCPには、すべてのグループが有効になっている69のツールが含まれています。組み込みのClaude、Codex、rigは48のライブツールを共有し、Braveキーが構成されている場合、`search_internet`も共有されます。保存用アダプターは`project`を追加し、ドキュメント操作、検証、入力ドメインの操作が共有されます。ランタイムの一覧、検出、ヘルプ、実行は一致します。保存された作曲／ライブラリ操作は、それぞれ別の目的を保持します。

完了したワークフローには、正確なノートバッチ、ミキサーのルーティングとパラメータ、楽器制御とオートメーション、クリップのレイアウトと作成済みのベンド/CCレーン、タイムラインマップ、パフォーマンスとレシピの編集、オーディオ/MIDIのインポート、トランスクリプションドラフトの承認、能力を考慮したボーカルコントロールとチェックポイントが含まれます。スナップショットジョブは、ライブドキュメントを保存せずに、保護されたプレビュー、配信用WAV/ステム、MIDIエクスポート、エンコードの検証を提供します。ワークフローと引数の例は、[agent workflows](agent-workflows.ja.md) と [audio delivery](agent-audio-delivery.ja.md) に文書化されています。

プロバイダー登録ストリップは制約を維持したままスキーマの文章形式で返します。保存済みのツールのコンパクトパラメータスキーマは合計38,450バイト、ライブツールのものは32,496バイトです。これらはプロバイダートークンのカウントではなく、UTF-8 JSONバイトです。`tool_help`はコンパクトスキーマと例を返します。`operation`は詳細なフィールド参照を選択します。

## 実際のエージェント

オプトインウィンドウテストは、3つのノートと別々のCC7レーンを備えた、保存されていない新しいフィクスチャーを使用します。トラックゲイン/パン、インデックス付きノートの更新1回およびCC64の置き換え、独立した読み戻し、プレビュー、MIDI、24ビットWAVの再生、そしてエンコードによる検証を要求します。完全なドキュメントの差分、関連のないノートおよびCC7の保持、Undoの3ステップ、Redo、未保存状態、実際のエクスポートファイルを確認します。

| バックエンド | モデル | 経過時間 | 結果 |
| --- | --- | ---: | --- |
| Claude Code | sonnet | 34.11秒 | 合格；古いリビジョンの拒否後にノートを再度読み戻した |
| Codex | gpt-6.1-sol | 33.25秒 | 合格；ツールエラーなし |
| Rig/Ollama | qwen3.8:27b, 64K, 思考なし | 300.33秒 | 合格；拒否された引数形式から回復 |

このフィクスチャは、バイパスモードと新しい出力パスを明示的に選択します。呼び出しは依然として実際のウィンドウホストと権限パスを越えて実行され、ユーザー設定やプロジェクトは変更されません。これは統合と正確な編集を確認するものであり、一般的なモデルの信頼性や音楽的リスニング精度を評価するものではありません。保存済みの試聴比較では、さらに新しいセッション間で変更不可能な音声バイトを検証するために、スクリプト化されたローカル批評家を使用します。

以前のローカルモデル試行では、誤解を招くポリシーの文章や過剰なフルヘルプが明らかになりました。共有ポリシーフレームワークは現在アクティブモードだけを記述し、ヘルプは操作に限定できます。32Kでは、より長いgpt-oss/Qwenワークフローでもコンテキストを使い切り、別のgpt-oss試行ではプロバイダーのJSONエラーが返されました。この記録は、部分的な編集を合格とみなさず、失敗と成功したツール呼び出しを区別しています。64KのGemmaも無効な呼び出しを行い、出力制限に達しました。Qwenは64Kでタスク全体を完了し、正確なドキュメント、Undo/Redo、エンコードファイルのチェックを含めました。これらの結果は、すべてのインストール済みモデルがこのワークフローを完了できることを意味するものではありません。

`AURIS_TOOL_SURFACE_EVAL`を`backend`、`model`、絶対的に新しい`output`フォルダー、`timeout_seconds`を含むJSONを指すように設定して、無視されたテストを実行します。オプションの`provider`、`url`、`api_key_env`、`context_tokens`、`thinking`は選択したトランスポートを設定します。テスト名は`ui::agent_chat::tool_surface_eval::installed_agent_edits_and_exports_the_unsaved_document`です。

<a id="saved-documents-and-regression-checks"></a>
## 保存されたドキュメントと回帰チェック

実際のstdio MCP検証では、別個のプロジェクトを作成し、正確なノート編集、変更のないリトライ、古いリビジョンの拒否処理、ミキサーストリップ、オートメーション、CC64、パフォーマンス、チェックポイント、数値/画像検査、プレビュー、検証済みのエクスポートを実行します。読み取り/エクスポート操作は、プロジェクトのバイトを変更させない必要があります。廃止名はリストから削除され、ディスパッチに失敗する必要があります。成功したstdio実行は、ステレオ48 kHz、24ビット、96,000フレームのWAVファイルで、フルスケールサンプルなしで0.90秒で完了しました。その単一の古いリビジョンの拒否と21件の廃止名拒否は、意図的な負のチェックでした。

このワークフローでは、既存のシリアル化欠陥が検出されました。スタンドアロンクリップは数値コントローラーキーを読み込みましたが、内部的にタグ付けされたトラックのデシリアライズではそれらを文字列として保持していました。コントローラーキーは現在、明示的にデシリアライズされます。回帰チェックは、JSONテキストおよび値の両方で、楽器、ドラム、シンガートラックに対してCC0/64/127をチェックします。保存されたMCPワークフローは、異なるツール呼び出し間で保存状態が維持されていることを確認します。

ワークスペーステストは4,327件に合格、23件を無視、失敗はなしで完了しました。Workspace Clippy、フォーマット、アプリケーション/MCPビルド、警告拒否のワークスペースドキュメントも合格しました。数値プレビューテストはソースを過負荷にし、減衰がオーディションにだけ影響し、フルスケールサンプルは使用されないことを検証します。キャンセル、古いジョブ、失敗したバッチ、正確な単位、無操作の永続化はセッション/ツールボックス/ホストの境界でカバーされています。音楽ライターやDSPアルゴリズムは変更されておらず、これらのチェックは生成された音楽の美的改善を主張するものではありません。
