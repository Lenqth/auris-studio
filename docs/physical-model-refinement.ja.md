# 物理モデルの改良

[English](physical-model-refinement.md)

これはコミット `5a6ccac` までの改良を記録したものです。その後の[実録音によるコピー合成キャリブレーション](physical-copy-synthesis.ja.md)に、現在のピアノ、ギター、バイオリンの工場設定と放射ゲインを記載しています。

改良の順序は、放射／ボディの音色、ギター、ピアノ、バイオリンです。試聴プローブと数値回帰は、完全な作曲測定を補足します。スペクトルフィットや学習スコアだけでは、楽器のリアリズムは立証できません。

<a id="radiation-profile"></a>
## 放射プロファイル

ピアノ、ギター、バイオリンは、90 Hzから10 kHzの固定中心周波数とQ = 0.9を持つ12個の広帯域パラメトリックフィルターを使います。ゲインは各楽器18個の一致ノート、つまりベロシティ0.5と0.85で9音ずつを48 kHzでレンダリングした結果から独立にフィットしました。平均化してパワースペクトルを平滑化する前に、各ノートをRMS正規化しています。参照はMuseScore Generalのパッチ0、25、40で、オプションのフォントライブラリから利用できます。参照ファイルのSHA-256は `ee51d2c4b1525e70f19a45909c4fd7a2e26d91d115fa89dbf5a6bc413d8b9bf3` です。

これらの係数は正則化されたスペクトル事前分布です。参照には励振、弦の振動、録音の着色が含まれるため、このフィットから独立した響板のインパルス応答やブリッジのアドミタンスを特定することはできません。ランタイムに波形は供給しません。各セクションのゲインは±6 dBに制限し、目標差は±12 dBに制限しています。ゲインの大きさと隣接ゲインの差にはペナルティを課します。ボディコントロールはドライ信号とカスケード出力を混ぜます。ホストレートの45%を超えるセクションは折り返さずバイパスします。ベース、ベル、マレットは元の3つの並列共鳴を保持します。

初期の公称フルウェットフィルターは、フィットした目標エンベロープ誤差をピアノで3.71から1.17 dB、ギターで7.76から1.12 dB、バイオリンで6.18から1.73 dBに下げました。これはフィッティング誤差であり、デフォルトのドライ／ウェット出力や知覚品質の測定ではありません。励振の改良は、同じ固定参照コホートに対する最終キャリブレーションの前に個別に評価します。

開発ツールでフィットを再現します。

```sh
cargo run -p auris-session --example physical_probe -- target/reference /path/to/MuseScore_General.sf2
cargo run -p auris-session --example physical_probe -- target/dry native dry
uv run tools/eval/fit_physical_body.py target/reference target/dry target/body-fit.json
```

JSONにはすべての入力のハッシュが記録されます。数値テストでは、DCゲイン、8–192 kHzで安定したインパルステール、ゲイン不変のフィット入力、楽器既存のピッチ、極端なパラメータ、ゼロアロケーションの契約を検証します。

最初の放射のみのチェックポイントは、ワークスペース全体のテストとclippy、3つのフィッター・テスト、ruffに合格しました。記号測定の出力はベースラインとバイト単位で一致します。9つのデフォルトシードによるネイティブ作曲では、平均Audiobox CE/PQが5.96/7.79から5.85/7.73に変化し、オーケストラとアンビエントはそれぞれCEで0.36/0.41低下しました。したがって、スペクトル事前分布だけを一致させても、報告された品質問題は解決しません。その後の励振変更は、このチェックポイントと元のベースラインの両方に対して評価します。

<a id="guitar"></a>
## ギター

有限の接触幅が初期の三角形変位を滑らかにします。速度とピックの硬さがこの幅を制御し、その後のループ損失はピックの硬さとは独立に減衰によって決まります。1次オールパスが分数調律遅延を供給し、フィードバックループで線形補間が生む高域減衰を避けます。位相は基音でキャリブレーションし、損失フィルターの正確な位相も含めます。分数遅延は0.5–1.5サンプルの範囲に収まります。

要求された基音減衰は、スカラーゲインと1極ローパスに分けます。どちらもパッシブです。基音のT60は `decay / (1 + 3 × damping)` であり、減衰はフィルターに割り当てる損失の割合も決めるため、高次モードほど早く消えます。ピッチベンドは約5 msで新しい周期に近づき、ベンド中は調律係数を8フレームごとに更新します。

音響出力は生の変位ではなく弦の運動速度に従います。一方、ピックアップブレンドは励振位置の変位コームを観測し、音響放射プロファイルをバイパスします。これはピックアップ形状の編集可能な近似であり、アンプモデルではありません。出力スケーリングは放射のみの試聴プローブのRMSに概ね合わせています。これにより、弦信号を微分したことによるデフォルトレベルの大きな変化を避けます。

テストでは、4つの音高と3つのレートで半秒間測定した基音減衰が要求損失から1.5 dB以内であること、接触とピックアップのスペクトル変化が独立していること、ベンドが正しいオクターブに収まることを測定します。実装全体で事前確保した弦ストレージを使います。

オールパス設計はSmithの[Extended Karplus–Strong algorithm](https://www.dsprelated.com/freebooks/pasp/Extended_Karplus_Strong_Algorithm.html)に従います。

ギターのチェックポイントはsynth、session、i18nのテストとワークスペースのclippyに合格しました。記号出力は同一です。全プリセットの平均CE/PQは5.89/7.74で、放射チェックポイントの5.85/7.73から変化しました。rockのCEは0.18、orchestralは0.13上昇し、他の7ケースは同一です。これは固定された単一シードの回帰コホートであり、一般的な知覚品質の推定ではありません。開発マシンでは、24ボイスのギターコールバックは48 kHz、256フレーム、最適化された開発プロファイルで平均0.077 msです。`physical_bench`で再現できます。

`uv run tools/eval/physical_ab.py before.wav after.wav comparison.wav` は、ピアノの変更前／変更後、ギターの変更前／変更後、バイオリンの変更前／変更後の順に試聴ファイルを生成します。各ペアのRMSを一致させ、ピークを0.9未満に保ち、ゲインをWAVの隣に記録します。入力は6モデルの`physical_demo`レンダリングで、標準の順序を使います。

<a id="piano"></a>
## ピアノ

ハンマーは、ベロシティ、接触の硬さ、音域に応じて持続時間が決まる有限の隆起コサイン力パルスを供給します。その単位積分された駆動が従来の初期モード振幅に置き換わり、接触時間そのものが励振を通じて高次倍音をフィルターします。このモデルは、解いたフェルト衝突ではなく、明示的な力パルスを持つ接触の縮約近似です。モード周波数は編集可能な剛性を保持し、基音で正規化します。

弦グループは65 Hz未満に1本、180 Hz未満に2本、それより上に3本あります。後者のグループはそれぞれ±0.9セント、±1.8セントだけデチューンします。各倍音は、複素モード状態を凸混合してユニゾンのメンバーを結合します。共通成分を保ち、差分運動を減衰させるため、エネルギーを増やさずに変化するうなりと減衰が生じます。ホストレートの45%未満では最大64倍音を保持します。各ボイスのストレージはprepareで確保します。1e-12未満のモード強度は、非正規化演算に入る前に休止させます。

テストでは、音域依存の弦数、短く硬い打撃の接触、追加された低音倍音、デチューン回転、ハンマー接触後のエネルギー収縮、可聴でないモードの休止に加え、共有するピッチ、ペダル、ベロシティ、剛性、アロケーションのチェックを検証します。初期の24ボイス実装は、開発プロファイルで256フレームのコールバックあたり2.254 msを消費しました。モードループから除算を外し、可聴でないモードを休止させることで、測定平均は0.831 ms、p99は1.704 msに低下しました。拡張された弦グループは従来の単弦モデルより高コストです。この測定は1台のマシンと1つのプロファイルについてのもので、レイテンシーの保証ではありません。

設計はSmithの[ピアノ合成](https://www.dsprelated.com/freebooks/pasp/Piano_Synthesis.html)に記載された接触、ユニゾン、結合の原則に従います。

ピアノのチェックポイントはsynthとsessionのテスト、ワークスペースのclippyに合格し、記号出力も同一です。9プリセットの平均CE/PQは5.82/7.71です。ギターのチェックポイントと比べ、pop-bandのCEは0.17、city-popは0.07、jazz-trioは0.33低下し、他の6ケースは変化しません。したがって、より豊かな励振モデルを学習スコアの向上として示しているわけではありません。固定された単音デモのピアノRMSは0.03651から0.03675に変化しただけで、A/Bユーティリティは引き続きレベルを一致させます。リリースプロファイルの24ボイスベンチマークは平均0.827 ms、p99 1.783 msです。

<a id="violin"></a>
## バイオリン

弓の接合部は連続的な弓テーブル散乱係数を使います。弓圧が固着範囲を決め、滑り摩擦はより弱く、滑り速度とともに低下します。摩擦は相対速度で制限されるため、相対滑りの方向を反転させたり、動く弓から独立にエネルギーを注入したりできません。力則は制限された縮約近似であり、完全な接触ソルバーではありません。接触の硬さは弦の損失とは別に滑り摩擦を調整します。

弓速は独立したパラメータで、ベロシティとCC11でスケールし、調整可能なモーションランプを持ちます。弓の接合部位置は波形バッファーをリセットせず15 msかけて移動し、損失はサンプルレートでスケールしたカットオフにおける減衰に依存します。ピッチ遷移は5 msで目標に近づきます。

オプションのレガートは、キーの繰り返し回数と最後のノート優先度を持つ固定128キーのテーブルを使います。重なったノートは、弦の波や振幅エンベロープをリセットせずに1ボイスを再ターゲットします。前のキーのオフは新しいノートを止めず、最新のキーを離すと以前に保持していたキーへ戻ります。All-notes／sound-offはテーブルをクリアします。レガートの切り替えを変更すると保持中のノートを解放し、多声／単声の遷移で追跡されない保持ボイスが残らないようにします。一般ボイスアロケーターの再ターゲット操作は帳簿だけを変更し、ボイスの測定済みレベルを保持します。デフォルトのバイオリンは多声のままです。セッションはメロディ役をレガートで開始し、パッドはより遅い弓運動と多声にして、明示的なコントロールを保持します。

テストでは、摩擦の受動性と連続性、同一音高のレガートで波形が完全に連続すること、正しい復帰音高と古いオフの扱い、多声のデフォルト、独立した運動／位置コントロール、弓の停止、レガートとライブ弓自動化でのゼロアロケーションをアサートします。

接合部はSmithの[bow/string scattering junction](https://www.dsprelated.com/freebooks/pasp/Bow_String_Scattering_Junction.html)にある進行波の幾何学に従います。[低音域の補正](physical-low-register.ja.md)には、連続力則、ベースピアノの分散、対応する測定を記録しています。

バイオリンのチェックポイントは、4,009件のワークスペーステスト、ワークスペースのclippy、6件のPython測定テスト、ruffに合格しました。記号出力はバイト単位で同一です。平均CE/PQは5.94/7.74です。ピアノのチェックポイントと比べ、ambientはCE 0.82／PQ 0.38上昇し、orchestralはCE 0.16上昇してPQが0.07低下し、pop-bandはCE 0.03上昇しました。24ボイスのバイオリンコールバックは48 kHz／256フレームで平均0.073 msです。

`physical_phrases` は、ピアノのコードと旋律、ギターのピッキングとストローク、レガートを有効にした重なり合うバイオリンのフレーズを含む、固定された編集可能なプロジェクトを保存します。各プロジェクトを変更前／変更後の凍結CLI実行ファイルでレンダリングし、2つのWAVディレクトリに対して `physical_ab.py --phrases` を使います。プロジェクトとノートイベントはレンダラー間で同一で、保存されたコントロールはすべて固定します。古い楽器は新しい弓／レガートコントロールを無視します。分離した単音の`physical_demo`比較では、工場出荷時のデフォルトの変化を別に取得します。

<a id="final-radiation-calibration"></a>
## 最終放射キャリブレーション

励振の変更によってドライスペクトルが変わり、特にギターの運動速度出力が変化します。`760e969` の後に同一の一致ノートキャリブレーションを再実行すると、初期のピアノ／ギターフィルターは固定参照に以前ほど一致しなくなりました。更新するのはこの2つのプロファイルだけです。バイオリンのプロファイルは、新しいフィットと同じ1.59 dBのフィッティング誤差をすでに持っています。

| モデル | ドライ目標差 | 最終励振での初期フィルター | 再キャリブレーション後のフィルター |
| --- | ---: | ---: | ---: |
| Piano | 3.75 dB | 2.35 dB | 0.98 dB |
| Guitar | 4.92 dB | 4.73 dB | 1.62 dB |
| Violin | 6.11 dB | 1.59 dB | 1.59 dBのまま |

これらは正則化された公称フルウェットのスペクトルフィッティング誤差です。デフォルトの混合出力や楽器のリアリズムは測定しません。すべての音高、ベロシティ、フォント、正規化、フィルターバンク、ゲイン境界、ペナルティは変更していません。この再キャリブレーションはAudioboxスコアとは独立して参照スペクトルを使います。`--prior initial-fit.json` をフィッターに渡すと、新しいプローブに対する事前フィルターを測定できます。ランタイムは楽器ごとに12個の固定ゲインを保持します。

<a id="final-comparison"></a>
## 最終比較

元のネイティブベースラインは `aaf5a0f` です。最終レンダラーには4つのモデル改良とピアノ／ギターの放射再キャリブレーションが含まれます。どちらの条件も空の `AURIS_SOUNDFONTS` ディレクトリと通常のセッションバランシングを使います。9つのプリセットはすべてデフォルトシード、48 kHz、32-bit WAV、レンダー末尾なしです。スコアライターや既存クリップは変更していません。

| プリセット | 変更前 CE | 変更後 CE | 変更前 PQ | 変更後 PQ |
| --- | ---: | ---: | ---: | ---: |
| chiptune | 5.84 | 5.84 | 7.88 | 7.88 |
| game-loop | 5.95 | 5.95 | 7.96 | 7.96 |
| pop-band | 6.35 | 6.08 | 8.05 | 7.94 |
| city-pop | 6.75 | 6.67 | 8.02 | 8.01 |
| rock | 7.20 | 7.40 | 8.20 | 8.29 |
| jazz-trio | 7.50 | 7.19 | 8.37 | 8.19 |
| orchestral | 4.85 | 4.73 | 7.32 | 6.99 |
| synthwave | 5.62 | 5.62 | 7.64 | 7.64 |
| ambient | 3.53 | 3.94 | 6.67 | 6.82 |
| Mean | 5.96 | 5.94 | 7.79 | 7.75 |

平均CUは7.482から7.490に、PCは4.377から4.506に変化しました。PCは予測されたシーンの複雑さを表し、高いことが本質的に良いわけではありません。結果は混在しています。rockとambientは改善しましたが、ピアノ主体のアレンジとオーケストラの制作品質は、試聴上の回帰ケースとして残っています。これらのモデル変更は演奏制御と物理構造を追加しますが、単一シードの学習評価だけではリアリズム全体の改善を立証できません。

最終検証は、4,009件のワークスペーステスト、ワークスペースのclippy、警告を拒否したドキュメントビルドに合格しました。6件のPython測定テストとruffも合格しました。記号出力は変更されず、SHA-256は `68a1be1d19d62d88d822022a67f7dd549e3875dd8f5cf6eb66800f18d6006496` です。凍結されたネイティブの変更前／変更後CLIハッシュは、それぞれ `f062b030d387bd131084f2302b9f24f4510a2238fa9fd09e2c5f2c7e1680764b` と `d81bc46a28685bcbb9ca13bd53c08c1be844bcf39c1d754b9e897cfad081b643` です。

試聴用アーティファクトは開発出力であり、リリース資産ではありません。

* `target/refinement-ab.wav`: デフォルトの分離ノート、ピアノA/B、ギターA/B、バイオリンA/B。
* `target/refinement-phrases-ab.wav`: 同一の保存済みコード／フレーズを両方のレンダラーで処理したもの。楽器とA/Bの順序は同じで、全体で約38秒です。
* `target/refinement-phrase-projects/`: 3つの編集可能なソースプロジェクト。

各ペアは共通のピーク制約でRMSを一致させ、ゲインマニフェストをWAVの隣に置きます。6秒のフレーズでは、ボディ量0.65とバイオリンのレガートを含む保存済みコントロールを固定します。変更前のレンダラーは新しい速度／レガートコントロールを無視します。アタック、減衰する倍音、弦のうなり、弓の開始／停止、遷移を全体レベルとは別に聴いてください。数値テストやフィッティング誤差から人間の試聴評価を推定していません。
