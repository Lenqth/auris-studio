# Gate 制作フィードバックの取り込み

2026年10月25日に提供された `Auris-harness-feedback.txt`、`regression-cases.json`、`evidence.json` を現行ソースと照合した記録。元の資料は saved_by 0.11.1 の制作経験であり、現行版の監査結果や全提案の合格証明として扱わない。既存の Gate プロジェクトと音源は変更していない。

## 音符と歌詞

`read_notes` の各音符に `timeline_index` を追加した。ページと `index` は従来の保存順を保ち、`timeline_index` はクリップ全体を開始 tick、保存 index の順で並べた順位を表す。全ページを同じ revision で取得してから時間順へ並べ、書き戻しには元の `index` を使う。

保存順が時系列と異なる音符、同時刻の音符、128音をまたぐページ、`write_lyrics` の時間順割り当て、読み戻した保存 index による編集を回帰ケースにした。モーラは既存の `analyze_lyrics` を使い、文字数で代用しない。

提供された `Gate-full-v4.auris` の track 3 / clip 24 も読み取りで照合した。98音のうち、保存 index 96 は tick 11040 の「を」、97 は tick 21120 の「ば」だった。新しい順序規則で計算した順位はそれぞれ20と38であり、元の編集アドレスを保持して途中の語位置へ戻せる。

## 音声批評

現行の `listen` は短い自由記述を受け取る。成功結果に `assessment_status: "unvalidated_response"` を付け、音声を送ったことや肯定的な文章を、検証済みの観察・選好と混同しないようにした。構造化評価が無効だった旧結果を、生の文章から成功へ戻すことも指示で禁止した。

不正な外側の JSON、未完了・空の応答には `audio_critic_invalid_response` を付ける。既存の接続失敗コード `audio_critic_connection_failed` は維持する。自由記述のキーワードから `observed` や `cannot_judge` を推測する処理は加えない。測定、別モデルの未検証所見、利用者の試聴コメントを分けて記録する。

## 長尺歌唱

現行の VOICEVOX アダプターには、隣接音と境界余白を含めて約20秒以内に収める分割合成が既にある。200秒の冒頭無音の後に歌が入るケースを追加し、要求の上限、絶対フレームの連続性、区間を切り出しても歌の位置と長さが保たれることを実 Engine を使わずに検査する。

既存のキャンセル試験は、prediction 後のキャンセルで次の decode を送らないことを確認する。発行済み HTTP 要求のサーバー側推論停止やメモリ解放を保証するものではない。スキルには、クライアント停止だけで完了と判断せず、未解決の処理へ重い要求を重ねないことを明記した。資料の約76 GBという観測を再現したとは扱わない。

## 制作と比較の手順

作曲指示と `auris-composition` の関連資料へ、次の判断を追加した。

- 人が手直しした譜面を新しい基準として保護する。聞き取りの修正では語のまとまりとリズムを保ち、全体の間隔拡大や主旋律の再生成へ直結させない。
- 重さ、発音グリッド、細かさ、荒さ、音数を独立した指定として扱う。拍頭中心という指定をジャンルの典型より優先し、伴奏へのクオンタイズを歌やソロへ広げない。
- 厚みは役割・帯域・発音・セクションの出入りで作り、音量をそろえて比較する。LUFSや帯域比だけで音楽的な改善や明瞭度を認定しない。
- MIXだけの変更では、現在の歌唱テイクを再利用する。局所の確認では、変更された区間と依存するバス／サイドチェインを扱い、最後に全曲を検証する。
- 検証用ミュート・solo・FX bypass は隔離スナップショット等で扱う。独立して非線形処理を通したステムを、フルMIXの加算成分とみなさない。伴奏確認には直接の伴奏レンダーを優先する。
- 無音の長さと復帰の最初の攻撃音を合わせて確認する。デジタルゼロと低レベル閾値、意図した歪みと符号化クリッピングを区別する。

これらは今回の制作から一般化できる判断手順であり、特定の助詞を伸ばす好み、40 msの復帰補正、特定の帯域比を固定規則にはしていない。

## 進行中の作曲 A/B との関係

24試行の作曲比較は、強化前 `3aa05ca7` と強化後 `1708a2f9` の凍結した指示、および同一バイナリで実行している。このフィードバックによる追加変更は、その比較に混ぜていない。別のビルド先 `target/feedback` でコードを検証するため、今回追加した判断の聴感上の効果がA/Bで実証されたとは扱わない。

## 検証

`auris-agent`、`auris-session`、`auris-singer`、`auris-toolbox` のライブラリテストは、合計1,410件が成功し、既存の22件が無視された。実行は `cargo test -p auris-session -p auris-singer -p auris-toolbox -p auris-agent --lib -j 2 --target-dir target/feedback`。最初の例も含むビルドはリンク時のPDB書き込み等で失敗したため、この成功結果を全実行対象のテスト合格とは表現しない。

`cargo fmt --all -- --check` と `cargo clippy --workspace --all-targets -j 2 --target-dir target/feedback` も成功した。

リポジトリ側とインストール済みのスキルは、同じ4つの参照文書を反映し、スキル検証を通した。別エージェントによる模擬制作シナリオでも、人が編集した旋律の保護、現在の歌唱テイクの再利用、未検証の批評を改善証明にしないこと、共有処理が不明なステムの減算を避けることを確認した。これは指示の適用確認であり、実際の制作・合成・試聴試験の代わりではない。
