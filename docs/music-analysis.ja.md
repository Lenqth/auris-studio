# 音楽分析

[English](music-analysis.md)

Auris は、書かれた音符からコードを推定し、音声から一定テンポとメジャー／マイナーコードを推定し、分離したモノラル音声を編集可能な音符ドラフトに変換できます。これらの処理は CPU 上で Rust の信号処理と固定テンプレートを使います。学習済み重みは読み込まず、GPU も必要ありません。再現可能な測定と現在の品質上の制限は [music-analysis-evaluation.md](music-analysis-evaluation.ja.md) にあります。

オプションの CPU モデルでは、楽器の存在タグ付けも利用できます。[ローカルモデルのセットアップ、ライセンス告知、測定済みの制限](music-analysis-models.ja.md)を参照してください。エージェントは、ローカルファイルやライブ添付には `transcribe_audio` を使い、`yin` または `basic_pitch` を選びます。付属の Apache-2.0 Basic Pitch ONNX モデルは外部の重みや Python を必要とせず、CPU 上で重なった音高の音符を推定します。最大10分／8チャンネルの音声を、通常の権限と Undo の経路を通じて編集可能なピアノトラックにできます。このドラフトは `import_transcription` と、返される `draft_id` で個別に承認します。[ピアノカバー評価](piano-transcription-evaluation.ja.md)には、作曲／音声ペアのベンチマーク、信頼度で制御するデコード、既存スコアの結果、残る未対応項目が記録されています。ローカル分析ツールを持つエージェントは、元の添付ファイルを書き出し、[認識器に依存しない API](transcription-api.ja.md) から外部の音符ドラフトをインポートすることもできます。長期的なモデルと計算資源のトレードオフは、[計算量の評価](music-analysis-compute.ja.md)で追跡しています。

<a id="use-the-desktop-controls"></a>
## デスクトップの操作を使う

**Analysis** メニューには、コード推定、音声分析、転写、楽器認識、ドラム測定があります。**Analyze Chords across Tracks** はプロジェクトを分析し、**Analyze Written Chords** は選択した音符トラックを分析します。既知のパーカッションとミュートされた素材は除外されます。デフォルトの解像度は4分音符1拍です。

音声クリップを選択し、**Analysis** から **Analyze Audio BPM / Chords** または **Transcribe Isolated Melody** を選びます。通常どおりファイルをインポートして、これらの操作を使います。分析は、エフェクトとタイムストレッチの前にトリミング済みソースを1回読み取ります。バックグラウンドワーカーが進行状況を報告し、専用の分析パネルからキャンセルできます。**Analysis → Analysis Results…** でパネルと承認操作を再び開きます。既存の同期デコード／リサンプル手順はキャンセルが検知される前に完了し、分析そのものはフレーム間で確認します。

**View Analysis Draft** にはコード候補とスコア、BPM 候補、転写を要求した場合は音符のタイムスタンプが表示されます。プレビューには最大256個の区間／音符が表示され、JSON 出力には完全な結果が含まれます。音声プレビューの時刻は元のソースの秒数で、クリップのトリムオフセットを含みます。書かれた音符の時刻は、0から始まる4分音符の拍です。

承認操作を使うまで、何も変わりません。

* **Apply Recognized Chords** は認識した区間を置き換え、ハーモニータイムラインの無音区間を消去します。不明な区間と分析範囲外のハーモニーは保持されます。シンボリック候補は、曖昧な候補を含め、個別に承認することもできます。
* **Add Draft as New Note Track** は新しい楽器トラックと編集可能な MIDI クリップを追加します。配置はソースクリップのトリム、ストレッチ、反復、プロジェクトのテンポマップに従います。元の音声はそのままです。生のタイミングを保持するため、既存の編集／クオンタイズツールで整えます。
* **Use as Clip Source BPM** は選んだ推定値を音声クリップのソーステンポとして採用します。プロジェクトのテンポマップは書き換えません。そのため、プロジェクトテンポに従うクリップは伸縮することがあります。

各承認は Undo の1ステップです。ドキュメントを編集するとレポートは無効になるため、編集後または1つの操作を承認した後に再度分析してください。音声バッファを置き換えても音声レポートは無効になります。承認されたコードは転回形やキー変更を含む既存のハーモニー表現を使い、承認された音符は既存の MIDI クリップを使います。レポートは一時的なもので、プロジェクト形式のフィールドは追加しません。

<a id="cli-and-model-tools"></a>
## CLI とモデルツール

次のコマンドは JSON を出力します。拍の引数は拍子記号とは無関係な、0から始まる4分音符の拍です。例のパスは自分の環境のパスに置き換えてください。

```sh
auris analyze-chords song.auris --track Piano --from-beat 0 --to-beat 32 --window-beats 1
auris analyze-chords song.auris --apply
auris analyze-audio recording.wav
auris transcribe-audio melody.wav
auris transcribe-audio melody.wav --midi new-draft.mid
auris transcribe-audio melody.wav --project song.auris --apply --at-beat 8 --name Melody
```

`--track` には `id:number` も指定できます。省略すると、音高のあるすべての音符トラックが選ばれます。既存プロジェクトを変更するには `--apply` が必要で、変更後はチェックポイント付きで保存されます。MIDI 書き出しには新しい転写だけが含まれ、拍0から始まり、既存の出力先を拒否します。`--at-beat` はプロジェクトへの挿入に使います。ファイル分析にはプロジェクト、オーディオデバイス、インポートは必要ありません。

MCP とエージェントのツールは、同じセッションコマンドを通じて `analyze_chords`、`analyze_audio`、`transcribe_audio` を公開します。引数スキーマには `apply`、拍位置、出力パスが記載されています。スコアはテンプレートとの一致または周期性を測るもので、**校正済みの確率ではありません**。

<a id="algorithms-and-practical-limits"></a>
## アルゴリズムと実用上の制限

書かれた音符の分析では、固定グリッド上で長さによる重み付きの音高クラスを蓄積し、オクターブとユニゾンの二重化に上限を設け、持続するベースを考慮します。12個すべてのルートについて、メジャー、マイナー、ディミニッシュ、オーギュメント、サスペンド、7th、6th のテンプレートを探索します。小さな動的計画法の遷移ペナルティで不要な変化を抑えます。結果はウィンドウごとに4つの候補を保持します。音高クラスが少ない、合意が弱い、解釈が同点、といった場合は不明のままです。これはハーモニーのラベル付けであり、キー検出や完全な機能分析ではありません。グリッド境界が変化のタイミングを制限し、短い経過音によって判定が変わることもあります。

音声は既存の帯域制限リサンプラーを使って11,025 Hzにリサンプルします。2,048サンプルの FFT とおよそ20 msのホップでスペクトルピークを抽出します。チャンネルの振幅は変換後にまとめるため、逆位相のステレオが相殺されません。0.5秒の音高クラスウィンドウをメジャー／マイナーテンプレートと比較します。A4 = 440 Hz の平均律を仮定します。倍音、パーカッション、デチューン、密な混合音で推定が混乱することがあり、音源分離はありません。

テンポは正のレベル変化とスペクトルフラックス、40〜240 BPM のオンセット自己相関、動的計画法によるビート整列を使います。最大3つのテンポ候補を出して、競合するパルスレートを示します。短い信号や非周期的な信号では推定値がないことがあります。レポートが推定するのは一定テンポ1つであり、ビートのタイムスタンプは拍子、ダウンビート、テンポオートメーションを示しません。

転写では、フレームごとに複数の連続した YIN 音高候補を保持し、固定コストの Viterbi デコーダーでビブラートや短い競合推定の中でも音符の識別を安定させます。比較する信号ウィンドウは報告されたタイムスタンプを中心とします。レベルゲートで休符を保持し、音高変化とレベルアタックで音符イベントを分割します。1つの分離された音高声部が同時に鳴ること、周波数が概ね65〜1,000 Hzであることを仮定します。約60 ms未満のイベントは除外します。各フレームの音高には最も強いチャンネルを使います。残響、重なる音符、息／ノイズ、広いまたは遅いピッチベンド、強い倍音で、音符の欠落や誤検出が生じることがあります。推定相対レベルは音符のベロシティに割り当てられますが、元の MIDI 演奏は復元しません。

リクエストは30分／8オーディオチャンネル、コード区間16,384個、音符200,000個に制限されます。バックエンドが保存するのは低レートの特徴量で、完全なスペクトログラムではありません。現在のファイルデコーダーは、分析時間の制限を確認する前にファイル全体を読み込み、クリップジョブはリサンプル前にトリムをコピーします。そのため、長い高レートファイルでは特徴配列だけの場合より大幅に多くのメモリを使うことがあります。ストリーミング時のメモリ上限は主張していません。

<a id="reproduce-the-baseline"></a>
## ベースラインを再現する

```sh
cargo test -p auris-analysis
cargo test -p auris-session --lib recognition
cargo test -p auris-gpui --bins music_analysis
cargo run -p auris-analysis --release --example measure_analysis
```

フィクスチャは明示的な音符リスト、無音、サイン波、コード、パルスタイミングから生成され、コーパス、チェックポイント、ネットワークを必要としません。数値テストでは12ルートのコード表記、曖昧さ／無音、ループと転回形、72/120/180 BPM のパルス、ビート整列、既知の音高と音符境界、キャンセルと無効なサンプル、逆位相ステレオを対象にします。セッションテストではキー／テンポマッピング、トリム／ストレッチ／反復、古いレポート、正確な Undo を対象にします。ウィンドウテストではヘッドレスアプリケーションを通じて承認ボタンを操作します。

測定例は、決定論的な3分、ステレオ、120 BPM、A4 のパルスフィクスチャを使い、経過時間、リアルタイム係数、テンポ候補、音符数を出力します。ファイルデコードとリサンプルを除いた準備済み音声バックエンドを測定します。これらの合成チェックが示すのは回帰動作であり、実録音の精度ではありません。より広い主張の品質ゲートには、研究計画のホールドアウト録音ベンチマークとサブグループ指標が引き続き必要です。

2026-09-07、Windows x86_64、AMD Ryzen 7 9800X3D、リリースビルド、逐次解析ワーカー1つの条件で、例はテンポ／コードに0.206秒、転写を含む全体に0.381秒かかりました（リアルタイム係数は0.0011と0.0021）。先頭 BPM 推定値は120.127で、転写は A4 の音符を360個返し、生成した360個のパルスと一致しました。これは単純な準備済みフィクスチャを使った暖機済みマシンでの1回の実行であり、実録音ベンチマークではありません。プロセスのピークメモリは測定していません。

CPU 転写の追跡評価、再現可能な変更前後の結果、現在の時間／メモリ測定は [music-analysis-evaluation.md](music-analysis-evaluation.ja.md) にあります。
