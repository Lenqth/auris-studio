# 音楽解析

[English](music-analysis.md)

Auris は、書かれた音符からコードを、音声から一定テンポとメジャー／マイナーコードを推定します。
CPU 上の Rust 信号処理と固定テンプレートを使い、学習済みモデルや GPU は必要ありません。
任意の [YAMNet ローカルモデル](music-analysis-models.ja.md)では楽器の存在を推定できます。

## デスクトップで使う

**解析** メニューから、選択したノートトラックや全トラックのコードを解析できます。
ミュートした素材と既知の打楽器は除外し、既定では四分音符ごとに解析します。

音声クリップを選び、**音声のBPM・コードを解析** を実行します。
エフェクトやタイムストレッチ前のトリム済みソースを1回分読み取り、バックグラウンドで解析します。
進捗表示からキャンセルでき、解析結果のパネルはメニューから開き直せます。
同期処理のデコードとリサンプリングは、完了してからキャンセルを確認します。

下書きにはコード候補とスコア、BPM候補を表示します。プレビューの上限は256区間で、JSONには全結果を含めます。
音声の時刻はトリム位置を含む元ソースの秒、書かれた音符の時刻は0始まりの四分音符単位です。

結果は明示的に受け入れるまでプロジェクトを変更しません。

* コードの適用は認識した区間と無音区間を更新し、不明区間と範囲外のハーモニーを保持します。
* ソースBPMの適用はクリップの元テンポを設定し、プロジェクトのテンポマップを保持します。

各適用は1回のUndoで戻せます。ドキュメント編集や音声ソースの差し替えで結果は無効になります。

## CLIとモデル向けツール

```sh
auris analyze-chords song.auris --track Piano --from-beat 0 --to-beat 32 --window-beats 1
auris analyze-chords song.auris --apply
auris analyze-audio recording.wav
```

拍は0始まりの四分音符単位です。`--track` は `id:number` も受け付け、省略時は全音程トラックを対象にします。
`--apply` はコードを適用してチェックポイント付きで保存します。音声ファイルの解析はプロジェクトや音声デバイスを必要としません。
MCPとエージェントは同じセッション処理を `analyze_chords` と `analyze_audio` で使います。

音声は11,025 Hzに変換し、2,048サンプルのFFTと約20 msのホップからスペクトルピークを抽出します。
チャンネルごとの振幅を変換後に統合するため、逆位相ステレオでも打ち消しません。
半秒ごとの音高クラスをメジャー／マイナーのテンプレートと比較します。
テンポはレベル変化とスペクトルフラックス、40〜240 BPMの自己相関、動的計画法で推定します。
短い音や周期性のない音には推定がない場合があります。スコアは確率ではなく一致度です。

上限は30分、8チャンネル、16,384コード区間です。デコーダーは長さ確認前にファイル全体を読み込み、
クリップの処理はトリム区間をコピーしてからリサンプリングするため、ストリーミング時のメモリ上限ではありません。
検証コマンドとアルゴリズムの詳細は [English](music-analysis.md) を参照してください。
