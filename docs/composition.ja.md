# 自動作曲

[English](composition.md)

テキスト仕様から曲全体を作成し、現在のコードに合わせて **Write It Again** で再生成できるクリップを作ります。アプリケーションのその他の機能については [Features](features.ja.md) を参照してください。

<a id="the-song-specification"></a>
## 曲の仕様

すべてのスタイルには、楽器に合った[非破壊のパフォーマンス設定](performance.ja.md#starting-from-automatic-composition)も組み込まれています。ギターのストロークやミュートの余韻、弱いピックアップ、共有フレージング、適切なソロパートのピッチジェスチャーなどです。各クリップの Performance タブで調整できます。`.asong` のルートフィールド `performance` は、曲名とは独立してこのパレットを保存します。

作曲では、ハーモニー、メロディー、伴奏の間で複数小節のフレーズを共有します。メロディーの頭部は発展させた尾部を伴って戻り、フレーズの終わりはアプローチ、保持、ブレスを形作ります。自動生成の器楽メロディーは、2拍のセルの中で短いジェスチャーと保持する着地点を組み合わせます。密度はジェスチャーを細分化し、シンコペーションはその準備を拍の外へ移し、writing style は保持、ピックアップ、先取りの配分を変えます。バリエーションは音型の冒頭を保ち、自動のフレーズ終端は最後の休符の拍の前に着地点を置きます。拍は複合拍子を含むメーターに従い、明示的なリズムパターンは指定された発音位置を保ちます。コードのボイシングは各声部の動きを考慮し、準備されたメロディーのサスペンションは順次進行で解決します。生成されたコード、スタブ、アルペジオは忙しい前景の周囲に余地を残し、最後のブレスに応答できます。ベースとドラムは拍を保ち、アンビエントテクスチャは持続するアタックを保ちます。

歌詞は実際のモーラの輪郭と語句グループを使用して、セクションの固定バー内のシードされたリズムパターンを選択します。リズムにはさまざまな長さ、ホールド、ピックアップ、ブレスが含まれ、すべてのモーラは残され、収まりきらないテキストは拒否されます。共有されたセクションメロディーは同じスロットを保持します。伴奏は実際の歌唱ノートを読み取ります。これらはすべてスコアの編集です：ピアノロール、歌詞、保存/読み込み、元に戻す、クリップの再生は通常の編集可能なノートで動作します。

| | |
| --- | --- |
| `chiptune` | 内蔵音声、4 to the floor |
| `game-loop` | ゲームの背景音楽用の16バーのチップチューンループ |
| `pop-band` | ドラム、ベース、キーボード、リード — 王道進行 |
| `city-pop` | 丸サ進行の上でピアノ、弓奏者のリードと撥奏者のベース |
| `rock` | ピックアップ付きギター、バイオリン弦、そしてハードキット |
| `jazz-trio` | 揺れるii-V-Iでピアノと撥弦ベース |
| `orchestral` | 3/4拍の弓弦、ギター、ベース |
| `synthwave` | 低音のボウ、マレットアッペジオ、そしてフォーオンザフロアキット |
| `ambient` | パッドと遅いベル、全くキットなし |

各プリセットはコードで組み立てた構造ではなく、ビルドに埋め込まれた `.asong` ドキュメントです。プリセット自体を読める形式にすることで、パーサーのテストにもなります。問題があれば黙って通さず、明確に失敗します。

プリセットは楽器コントロールと、順序付きのインサートエフェクトも保持します。Rock のリードギターとリズムギターはブリッジピックアップとドライブさせたクローズドキャビネットの Guitar Amp、クリーンギターとアルペジオはクリーンな増幅を使います。Pop と city-pop のギターは軽い増幅とコーラスを使い、synthwave のギターアルペジオにはコーラスと8分音符のステレオディレイを加えます。既存の共有ルームリバーブもミックスの一部として残ります。ラウドネスのバランス調整では、フェーダーを設定する前にこれらの完全な信号チェーンを測定します。

`.asong`ファイルでは、部品の`params`がその名前付きのネイティブ楽器のコントロールを上書きし、`effects`が処理順にインサートをリストします。エフェクトエントリは、エフェクトのコントロールでキー付けされたレジストリの`id`とオプションの`params`を使用します。たとえば：

```toml
[[part]]
name = "lead"
instrument = "auris.physical.electric_guitar"
params = { pickup_position = 0.064146 }
effects = [
    { id = "auris.fx.guitar_amp", params = { drive_db = 34.0, cabinet = 2.0, output_db = -12.0 } },
]
```

`effects` を省略すると、自動の役割/GMインサート規則が適用されます。`effects = []` は空のチェーンを指定します。仕様は保存と再生成を通じてこれらの選択を保持し、生成されたプロジェクトの通常のミキサーと楽器コントロールは引き続き編集できます。

`pop-band` のフォームは、最初の2つのコーラスそれぞれの前に4小節のプレコーラスを置き、その後に8小節のブリッジと最後のコーラスを続けます。プレコーラスは別のコード進行上で ii から V へ上昇します。ブリッジは vi から始まり、キーボード、ストリングス、ベース、リードが入り、最後にフルバンドが戻ります。2つ目のプレコーラスと最後のコーラスには別々の歌詞があり、元のボーカルメロディーを共有します。

**セクションは、別のパート宣言ではなくパッチとして、パートの演奏方法を変更できます。** 指定しない項目には触れないため、より忙しいコーラスも1行で表せます。最後のコーラスでリードを1オクターブ上げる、ブリッジでハイハットを16分音符にする、1セクションだけリズムを書き出す、といった指定を `octave`、`density`、`gate`、`subdivision`、`rhythm`、`note` として `[section.chorus.part.lead]` の下に記述します。

意図的に*パッチできない*のは、名前、役割、楽器、プログラム、レベル、パンです。これらはパートの演奏方法ではなく、パートの**トラック**としての属性だからです。パートは曲全体を通じて1トラック、1行、1楽器、1フェーダーです。ヴァースをピアノ、コーラスをストリングスで演奏したい場合は2つのパートであり、上部のパート一覧ボタンからそれぞれを追加します。これは将来解除する制限ではありません。途中で楽器が変わるトラックは2トラックになるため、最初から2パートだったことになります。

**キーが変わるセクションには導入が付きます。** 変更前の最後のコードが、到達するキーのドミナントセブンスになります。これは古くからある手法で、モジュレーションを編集ではなく到着のように聴かせます。`V7` がトニックの音が鳴る前にそのトニックを示すため、セクション開始時には耳がすでに新しいキーに入っています。これは手動で要求された変更の直前の小節に、コード1つを置き換える処理です。名前で引用した進行の小節を書き換える唯一の仕組みで、単純なジャンプを意図する場合は `lead_in = "none"` とします。

[`examples/`](../examples) に2つあります。`hello.asong`は3行で、各フィールドにデフォルト値があるため、一曲全体です。`neon-drive.asong`は、各部分の横にコメントが付いた語彙の大部分です。

```bash
auris compose examples/neon-drive.asong -o neon.auris
```

```toml
title  = "Neon Drive"
key    = "C minor"
tempo  = 128
mood   = "driving"
chords = "@marusa"
form   = ["intro", "verse", "chorus", "verse", "chorus", "outro"]

[section.chorus]
bars      = 8
intensity = 0.95
tempo     = 132

[[part]]
name       = "lead"
instrument = "auris.synth.chiptune"

[[part]]
name    = "strings"
role    = "pad"
program = "String Ensemble 1"
```

`instrument`はプラグインの名前を指定します；**`program`は一般MIDIサウンドファミリー**を、名前または番号で記述します。サポートされているファミリーは、編集可能なネイティブ物理楽器と組み込みドラムキットを選択します。その他のファミリーは、オプションでインストールされたGMSoundFontを使用し、それからパートの`instrument`を報告用フォールバックとして使用します。また、`auris.physical.violin`のように物理プラグインを直接名前付けすることもできます。モデルとそのコントロールについては[physical instruments](physical-instruments.ja.md)を参照してください。

明示的な`source`は、選択されたライブラリアセットを記録します。SoundFontバンクとパッチは、一般MIDISoundFontを除くファイル独自の識別子（0–65535）を使用します：

```toml
[[part]]
name = "keys"
role = "chords"
source = { type = "sound_font", path = 'C:\Sounds\Keys.sf2', bank = 257, patch = 301 }
```

CLAPの場合、`source = { type = "clap", path = 'C:\Plugins\Instrument.clap', plugin_id = "vendor.instrument" }`を使用してください。VST3の場合、バンドルのクラス識別子と`type = "vst3"`および`class_id`を使用してください。ライブラリはこれらの識別子を自動的に生成します。`source`と`program`は同時に指定できません。現在のドキュメントが置き換わる前に、明示的なソースが正常に読み込まれる必要があります。利用できないファイルやエフェクト専用プラグインはエラーを報告します。保存されたプロジェクトや仕様は選択を保持し、**Collect Assets**は収集されたSoundFontパスを更新し、別のテイクを再開して作曲できるようにします。

**ドラム**部分では、同じフィールドが全く異なる意味を持つことがあります。これはGeneral MIDIではそうだからです。パーカッションパッチは*キット*全体（`"Standard Kit"`、`"TR-808 Kit"`、`"Brush Kit"`）を選択し、ドラムを選択するのはノート番号です。`role`がすでに指定しているため、数字がどの読み方になるかは決して推測できません。

構文は TOML で、拡張子は `.asong` です。プロジェクトファイルが `.auris` 内に JSON として保存されるのと同じ考え方です。Serde が読み書きするため、保存ダイアログが同じ文法を別実装して食い違うことがありません。セクションは名前をキーとするテーブルです。順序は意味を持たず、再生順は `form` が決めます。パートはトラックを作る順序を表す配列です。未知のフィールドは無視せず拒否するため、スペルミスが黙って消えることはありません。構文エラーには行番号が示され、意味に関するエラーはまとめて報告されます。

進行はカタログから名前で引用することができます - `@marusa` (丸サ進行)、`@royal-road` (王道進行)、`@koakuma`、`@komuro`、`@canon`、`@junjo`、`@blues`、`@andalusian`、そしてそれ以外 - またはローマ数字で書くことができます (`| IVmaj7 | III7 | vi7 | I7 |`) 任意のキーで。引用された進行は決して色が変わることはありません。なぜなら、あるものを名付けることの全目的は、それが自分自身のように聞こえることですから。

引用した進行は、キーのモードが進行を書いたときと異なる場合、度数ではなく**コード**を基準に解釈します。丸サ進行は長調向けに書かれています。C短調で指定された場合は、曲の中心に合う関係調のループとして Abmaj7、G7、Cm7、Eb7 と読みます。これはコードを1つしか共有せず、着地点も大きく異なるエオリアン・スケール上の `IVmaj7 III7 vi7 I7` ではありません。逆方向も同様です。短調の度数で書かれた `@epic` は、曲が長調なら関係短調上のループになります。自分で書き出した進行はモードを宣言せず、指定した度数をそのまま解釈します。

進行をまったく指定しない方法もあります。`chords = "?"`（または `[harmony]` の項目を `"?"` にする）と、作曲者に進行の発明を求められます。カタログが使う動きを重み付きでたどり、長調の項目から数えるため、王道進行の V → iii も語彙に含まれます。それをドミナントへ向かう4小節フレーズ2つに組み立て、ムードの緊張が高まると `| ii V |` の小節が現れます。結果はシードとチャート名に対して決定論的です。`seed = 7` は常に同じコードを作り、繰り返されるセクションは同じセクションになります。作曲者独自の進行なので、ムードによる再調整やターンアラウンドの傾きが適用されます。

各パートは、セクションごとに発明された短い音型を作り、それを小節ごとに繰り返します。これにより耳に残るまとまりが生まれます。各フレーズの4小節目は、もう一度繰り返すのではなく応答になります。同じセクションを2回演奏すれば、2回とも同じセクションです。`variation = 0.4` なら必要な分だけ変化を戻せ、`variation = 0` なら2回目のコーラスは1音ずつ最初と同じになります。別のセクションが続く場合はそこへフィルを流し込み、各パートは全体を一定レベルで平らにせず、フレーズに沿って穏やかに動きます。

パートが選べるノートはキーだけでなく、その下のコードから決まります。借用コード（セカンダリードミナントや上げたリーディングトーン）はノートを追加せず、そのノートが属していた度数を*置き換えます*。単純なスケールから作ったメロディーが置き換え前の度数を鳴らし続けると、2つの音が同時に鳴ってしまいます。したがって C マイナーの G7 上で使えるノートは `D Eb F G Ab B` です。これは名前で指定したものではなく、到達した結果としてのハーモニックマイナーです。

作曲された曲は**書かれただけでなくミックスされた状態で届きます**。レベルとパンは役割に応じて配置され、キットは1つのドラムフェーダーの下に置かれます。ピッチを持つパートにはルームリバーブを送り、パッドには最も多く、リードには少なく、キックとベースには送りません。空間が広いほど遠くに聞こえるためです。キットは、1980年頃以降の多くのレコードと同じく、リードの*上*に置かれます。各トラックは並び順ではなく演奏内容に応じて色分けされるため、名前を読まなくてもアレンジを把握できます。

すべては仕様とそのシードの純粋な機能であり、同じドキュメントは常に同じセクションを書き、`--seed 7`は異なるものを書き込む。すべての決定は呼び出し順ではなく名前で指定されたストリームから導き出されるため、ドラムの密度を変更してもメロディーが静かに書き直されるわけではない。`auris progressions`はカタログをリストアップし、`--set "field: value"`はコマンドラインからの任意のフィールドをオーバーライドし、値はTOMLが引用する形式ではなく、あなたが言うように書き込まれる — `--set "key: D minor"`。

<a id="looping-background-music"></a>
## ループする背景音楽

ループモードでは、最後に伸ばすコードやフェードアウトを追加しません。フィルは冒頭へ戻る流れを作り、最後のセクションが別キーなら冒頭セクションの `lead_in` に従って戻りを準備します。明示的に要求した転調を除き、引用されたコードは変わりません。生成されたプロジェクトでは完全なフォームをサイクル再生でき、保存・再開時にも設定を覚えています。

**File → Export Cycle…** は正確に1つのサイクルを書き出します。録音前に楽器やエフェクトをウォームアップするため、リバーブやディレイがファイルのテールで延長されることなくオープニングに持ち越されます。これにより、リピートのための境界が整います。フリーランニングやランダムなプラグインモジュレーションは、パスごとに異なる結果が出る可能性があります。

```bash
auris compose --preset game-loop -o GameBGM.auris
auris render GameBGM/GameBGM.auris --loop -o GameBGM.wav
```

`.asong`で`ending = "loop"`を設定する場合、CLIとモデルツールもオーバーライド用の`ending: loop`を受け付けます。[game-loop.asong](../examples/game-loop.asong)は完全な例です。

<a id="clips-that-write-themselves"></a>
## 自動生成クリップ

曲全体の仕様がなくても、その下にあるコードから1つのクリップを生成できます。メロディー楽器トラックの空き区間を右クリックし、リード、コード、パッド、アルペジオ、ベースのいずれかを生成します。ドラムトラックにはフルキット、キック、スネア、ハイハットのプリセットがあります。ドラムを別トラックにすれば、ミキサーのレベルと処理を独立して制御できます。

新しいクリップは、右クリック位置を含むセクション内の空き区間を埋めます。同じトラックにある既存クリップが左右の端を決めます。最後のセクションでは、ポインターより先にプロジェクト内の既存クリップの終端があれば、そこを終端にします。セクション境界がない場合、フレーズはポインターの小節から始まり、最大4小節で、近くのクリップまたはセクション境界で止まります。占有された位置をクリックして重なるパートを追加することはできません。

クリップは生成に使ったレシピを保持します。そのため **Another Take** は次のシードを使い、**Write It Again** はコードが変わると追従し、**Keep This One** は採用したテイクからレシピを削除します。トラック固有のメニューには **Keep Every Take Here** もあり、すべてのクリップに一括適用して、対象数を表示します。ダイヤルはインスペクターにあります。

生成されたメロディッククリップを選択すると、インスペクターで**Session Player**を開きます。5つのロールボタンはリード、コード、パッド、アルペジオ、またはベースを選択し、現在の選択をハイライトします。ドラマーが使用する同じXYパッドは、水平方向に**Complexity**（レシピの密度）、垂直方向に**Intensity**（強度）を制御します：右にドラッグするとパートがより活発になり、上にドラッグするとパートがより強くなります。表示値には両方の値が表示されます。各ドラッグ操作で選択したクリップは1回のUndoステップとして書き換えられ、シード値とパフォーマンス設定は保持されます。

**Phrasing** グループには、サブディビジョン、−2〜+2の5つのオクターブボタン、適用可能な表現スライダーがあります。**Takes** グループには、編集可能なテイク番号（シード）、**Write It Again**、**Another Take**、**Keep This One** がまとまっています。コードを編集した後に **Write It Again** を使うと、現在のテイクのままコードに追従します。**Keep This One** はノートを残し、生成コントロールを削除します。これらは選択中のクリップを編集するため、同じ楽器トラックでもセクションごとに異なる設定を持てます。

コントロールの意味は次のとおりです。

| | |
|---|---|
| **サブディビジョン** | ビートがどれほど細かく分割されるか：1/8、1/16、またはそれらのいずれかをトリプルで |
| **オクターブ** | プリセットが置かれている場所から±2のどのレジスターですか？ |
| **密度** | パートの忙しさは、75%を超えるコードがサブディビジョンをより多く埋め、100%ですべてのステップに到達することによって決まります。 |
| **シンコペーション** | ビートからどれだけ離れていても、忙しくならないようにどうやってうまくやっていくか |
| **ゲート** | 各ノートが次のノートまでの間隔の割合としてどれくらい鳴るか |
| **強度** | どれだけ難しいですか |
| **ダイナミクス** | 最も硬い音と最も柔らかい音が打たれる間隔はどれくらいですか？ |
| **埋める** | ドラムのみで、スネアが続く部分にぶつかる最後のバーのどれだけですか。 |
| **スイング** | オフビートはどれくらい遅いですか？ |

強度とダイナミクスはレベルと拡散度であり、二つの異なる質問であるため別々に考えられます。あるパートは強く平坦に演奏されることもあれば、すべてが動きながら優しく演奏されることもあります。0ではダイナミクスは打たれたすべてのノートを同じように処理し、シーケンサーはそれがまさにポイントとなることもあります。そしてレベルは拡散度とともに沈むのではなく、強度が設定したまま維持されます。それはすべてのバリエーションの源を同時に捉えます：メトリックの階層、アクセント、フレーズ全体にわたる軽さ、そしてドラムフィルのクライマックス。

ダイナミクスダイヤルは意図的に上部に狭くなっています。部品のストロークはそこではそのレベルの約10分の1以内に収まります。これはバンドフレーズです。幅が広くても同じアイデアは、プレセット全体で測定して調整するまでそうだったように、練習していないバンドのように聞こえます。

クリップをどれだけ*ルーズに*演奏するかは、レシピのダイヤルではありません。タイミングとベロシティの揺らぎであるヒューマナイズは、独自のスイングとゲートとともにクリップの **Performance** セクションにあります。これは何を言っているかではなく、どう演奏するかの設定です。ピアノロールはノートを常にグリッド上に表示し、クリップを書き直さずに揺らぎを調整できます。ループするクリップは再生ごとに異なる揺らぎになります。生成クリップにはパート固有のフィールが初めから設定され、ダイヤルを最大にしても、どのテンポでもピッチを持つノートは記述位置から6 ms以内に鳴ります。ドラムキットは、ドラマーが拍を保つことを基準にして、一定の傾きだけを保ちます。

キットは中央付近の密度を読み取り、中央では**グルーヴを演奏します**。拍は決して間引かず、弱い16分音符だけを間引くことがあり、静かなセクションではさらに薄くなります。中央より下では最も弱いヒットから上へ向かってグルーヴを薄くしますが、ダウンビートは失いません。中央より上では、グルーヴが空けていたステップにゴーストノートが入り、別のことを演奏しなくてもドラマーが忙しくなります。どのリズムを演奏するかはグルーヴピッカーが決めます。これは数値ではなく、ドラマー固有の語彙から選ぶものです：`basic-rock`、`eight-beat`、`sixteen-beat`、`four-on-the-floor`、`shuffle`、`breakbeat`、`bossa-nova`、`half-time`、`sparse`。

プリセットが実際に聞かせられる行だけを描画します。キットにはゲート、サブディビジョン、オクターブ、シンコペーションがありません。ワンショットはノートオフを無視し、ピッチではなくドラム番号で鳴り、どこで鳴るかはどのグルーヴを使うかで決まります。フィルを持つのはキットだけです。他のパートには、フィルを知らせる最後の小節がないからです。パッドにシンコペーションはありません。各コードをそのコードの位置で鳴らすためです。3連符グリッドのパートにスイングはありません。

サブディビジョンは曲単位ではなくパート単位です。そのため、ストレートなドラムキットの上でスタブを3連符にすることは、衝突ではなく設定です。3連符グリッドではスイングが消えます。スイングが押そうとする位置にグリッドがすでにあるためです。ドラムキットはサブディビジョンを完全に無視します。グルーヴは16分音符で書かれ、インデックスで読み取られるからです。

コードパートはセクションごとに音型を1度選び、キーボード奏者がフィールを決めて維持するように繰り返します。予定されたフレーズの終わりの小節だけが、時折その音型を反転させます。密度が75%を超えるとコードは推進力のある音型を保ち、サブディビジョンをより多く埋めます。100%ではすべてのステップを鳴らします。1/16サブディビジョンの4/4では1小節16アタック、1/16の3連符では24アタックです。前景を意識したアレンジでは、この明示的な高密度リズムを保ちます。手書きのリズムは密度にかかわらず休符を保ちます。

**Chords** と **pad** は同じ作曲家が同じハーモニーを読みます。違いは、コードが変わるときのパッドの動作です。パッドは2つのコードに共通する音を保ち、進む先のある声部だけを動かします。コンピングはすべての音を再び鳴らします。これがコードが*変化する*ことと*漂う*ことの違いであり、リズムをオフにした1つのプリセットではなく2つのプリセットに分ける理由です。

短い繰り返しピアノコードの場合、**Chords**を選択し、密度をほぼ100％、サブディビジョンを1/16、ゲートをほぼ30％に設定してください。密度はアタックを制御し、ゲートはその長さを制御します。タイミングをよりタイトにするには、Performance humanize量を下げてください。プリセットを変更すると、意図的に調整されたダイヤルは保持されます。

```toml
[[part]]
name = "kick"
note = 24     # this font puts its kick on C1
```

`auris`の構成仕様は、各部品ごとに同じ設定に到達します。

```toml
[[part]]
name        = "chords"
subdivision = "16t"
gate        = 0.25
```

<a id="a-whole-song-is-clips-that-write-themselves-too"></a>
### 一曲全体が自動生成クリップです。

レシピは、**そのセクションが演奏した状態の**パートから読み取られます。コーラスでベースを1オクターブ上げれば、そのことを記録したコーラスクリップになります。レシピはクリップそのものであり、作成過程の録音ではありません。この違いには、知っておくべき目に見える結果があります。

> **作曲されたクリップをもう一度書いても、最初に届いたノートは戻りません。** 曲全体には、1つのクリップには収められない計画があります。繰り返しセクションが最初の演奏からどれだけ変わるか、何が何を導くか、フォーム全体の強度の弧などです。書き直しでは、そのクリップを **Write a Part Here…** と同じライターに渡します。そのライターはドキュメントのコードを知っていますが、曲全体の計画は知りません。保持されるのはクリップが*意味する*もの、つまり同じパート、同じ音域、同じ密度、同じコード上で同じように演奏されることです。変わるのはフレーズです。

構成されたクリップの端をドラッグすることも同様です。これは新しいスパンに書き換えるというリクエストであり、手書きで作成されたクリップの場合と同じです。テイクが保持される場合は、まず「このテイクを保持」してください。

構成された曲も**ミックスされた**状態で到着します。作曲の最後のステップは、各パートを個別にレンダリングし、実際の音量を確認し、そのパートにふさわしい位置にフェーダーを調整することです。その後、全体の曲を−14 LUFSに上げます。これは数秒かかり、それが理由です。作曲家が*パート*を選択し、セッションがその楽器を解釈するため、聴くことなく決定されたレベルは、まだ誰も聞いたことのない楽器についての推測に過ぎません。曲が再びそれが必要な場合、Composeメニューの**バランスの調整**が有効になります—詳細は[feature notes](features.ja.md#setting-the-levels-by-listening)をご覧ください。

<a id="accompanying-something-you-played"></a>
## あなたが演奏したものを伴うもの

作曲者は逆向きに読み取ります。クリップにメロディーを入力します（手作業、MIDIファイル、キーボードのいずれでも構いません）。そのクリップを右クリックして **Accompany This Melody** を選ぶか、選択した状態で **Compose → Accompany the Melody** を使います。

起こるのは3つのこと、1つのUndoステップで：

1. メロディーの**キー**を推定し、クリップの開始位置のハーモニーレーンに書き込みます。
2. メロディーが含む小節数だけ、下に**1小節につき1コード**を書き込みます。
3. **ベース、コード、ドラム**をメロディーの横にトラックとして追加します。メロディーの上に重ねるのではありません。メロディー自体は変更しません。

各パートは一般的な生成クリップです。レシピを持っているため、上記のテーブルにある各ダイヤルはすべて適用されます。**Another Take**は異なるバンドを提供し、**Write It Again**はコードの動きに合わせて動きます。各パートには、編集可能な楽器パラメータを備えた、適切なネイティブサウンド（物理ベース、ピアノ、内蔵ドラムキット）が付属しています。

<a id="what-it-can-and-cannot-know"></a>
### それが知ることができることと知ることができないこと

キーは、メロディーが実際に演奏する音を、各ノートの保持時間とベロシティで重み付けし、Krumhansl と Kessler が1982年に測定したプローブトーン・プロファイルと照合して求めます。これは機械的なキー推定の標準的な基盤であり、スケール理論ではなく聴取者の評価に基づきます。各小節のコードは、その小節を最もよく説明するキー内7つの三和音から選びます。小節がどこに到着するかを少し重視し、進行がコイントスのように毎回変わらないよう慣性も加えます。乱数は使いません。同じメロディーは常に同じ読み方になるため、1音だけ変えて再実行すれば、その音がハーモニーにどう作用したかが分かります。

メロディーは1声部なので、そこから生じるすべての問いには答えられません。予想される失敗は2つです。**関係調の取り違え**（Aマイナーの曲を、全音が共通する Cメジャーとして読む）と、**経過音の小節**を経過先のコードとして読むことです。どちらも完全には解決できませんが、行き止まりでもありません。推定結果はハーモニーレーンに表示されるので、確認して書き直し、生成クリップで **Write It Again** を選んで修正後のハーモニーに追従させられます。

ノートのないクリップは伴奏を拒否します。読み取るメロディーがなく、何もないところから書いたベースラインは、伴奏する対象もないからです。
